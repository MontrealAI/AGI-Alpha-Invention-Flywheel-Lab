## Concrete contribution

The research component does something that the earlier fixed seven-operation `flywheel/strategy.py` grammar does not: it can search an extensible, **typed, monotonic causal composition** and identify a lower-cost sequence when a new intermediate interface is supplied. It creates a source-bound candidate, independently replays prerequisites, order, effects and costs, then exports a capability capsule with **empty current proof and authority**.

`mechanism_harness/evidence.py` adds a deliberately narrower categorical source-group correction example. Its apparent recovery is **conditional on the declared source-group independence and maximum corruption budget**. Repeating results from the same source is not an additional independent vote. Correlated wrong sources can still yield a coherent wrong answer; the package cannot discover that truth without an external anchor. This **does not implement** the exact nonlinear Out-Reflect theorem from the paper; it exercises a separate, limited evidence-control contract.

The package allows no external side effects: `pure` and `public_read` are the only admitted *descriptive* effect classes. There is no dispatcher capable of executing real-world writes. Candidate bridges are **not automatically qualified**. The examples are developer-authored; no autonomous novelty is claimed. Their integer resource units are developer-declared and are **not monetary costs, CPU invoices, customer value, or profit**.

## Reproduce

Run from repository root with Python 3.12+ and no paid model, credentials, or network:

```sh
python3 -m unittest discover -s tests -p 'test_mechanism_harness_026.py' -v
mkdir -p /tmp/agi-alpha-mechanism026-new
python3 -m mechanism_harness compose \
  --spec campaign/mechanism-harness-026/EXAMPLE.json \
  --output /tmp/agi-alpha-mechanism026-new/PLAN.json
python3 -m mechanism_harness audit \
  --spec campaign/mechanism-harness-026/EXAMPLE.json \
  --plan /tmp/agi-alpha-mechanism026-new/PLAN.json \
  --output /tmp/agi-alpha-mechanism026-new/CHECK.json
python3 -m mechanism_harness capsule \
  --spec campaign/mechanism-harness-026/EXAMPLE.json \
  --plan /tmp/agi-alpha-mechanism026-new/PLAN.json \
  --check /tmp/agi-alpha-mechanism026-new/CHECK.json \
  --output /tmp/agi-alpha-mechanism026-new/CAPSULE.json
python3 -m mechanism_harness reflect \
  --spec campaign/mechanism-harness-026/REFLECTION.json \
  --output /tmp/agi-alpha-mechanism026-new/REFLECTION_RESULT.json
python3 -m mechanism_harness experiment \
  --spec campaign/mechanism-harness-026/EXAMPLE.json \
  --successor campaign/mechanism-harness-026/FRESH_SUCCESSOR.json \
  --reference campaign/mechanism-harness-026/REFLECTION.json \
  --output /tmp/agi-alpha-mechanism026-new/STUDY.json
```

All output paths are create-only and must be fresh. Do not use this CLI to mutate an existing native account. It operates only on public data-only JSON specifications and prints compact status information. Symlinks, duplicate JSON object keys, unsupported effects, unknown schemas, unsorted or duplicate fact names and invalid step order are refused.

## Preserved test case and result

`EXAMPLE.json` specifies a synthetic source-grounded-deliverable goal. The existing direct method has **20 hypothetical cost units**. A five-stage composition with an explicitly **developer-supplied proposed connector** has **9 hypothetical units**. `FRESH_SUCCESSOR.json` changes the surface task to a synthetic API-migration case; its direct method has **19** and its composition **11**. Both proposed connectors still require independent qualification and actual executable semantics; this is *not* a demonstration that the same inherited mechanism benefits a fresh successor. The `RESULT.json` file says so explicitly.

The separate three-source, one-source-fault categorical example returns a conditional answer. The tests include a beyond-budget case which can mislead it, plus contradictory same-source and insufficient-group refusals. Thus the reference group assumption is never silently converted into an unconditional truth claim.

## Trust/operating boundaries

- A mechanism advertises facts it *would* produce under the supplied symbolic model. The harness does **not** establish that a real tool actually produces them.
- A proposed bridge appears in a plan only as `CANDIDATE_REQUIRES_INDEPENDENT_QUALIFICATION` with its supplied provenance. Its presence never establishes autonomous invention.
- The independent replay of a plan establishes syntactic/precondition/cost consistency within the same author-supplied ontology, **not** independently correct external semantics.
- `current_proof: null` and `authority: []` are mandatory in exported capsules. A P0 service must obtain its own permission and independent mission proof before execution.
- `NO_SUPPORTED_PLAN_FOUND_WITHIN_BOUNDS` does not prove global impossibility; the search is bounded by states, steps, and author-specified cost units.
- Source-gated acceptance and commercial receipts remain exclusively within the existing enterprise and its independently audited native financial owner.
- No scheduled task, model API, production deployment, paid outreach, blockchain fee or autonomous capital commitment is introduced.
