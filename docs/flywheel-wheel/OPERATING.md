# 🌌♾️ Flywheel Harness 030 — circular read-only operator

This is a real **circular** Flywheel Harness visualization and a source-bound **read-only view** over the canonical completed simulated enterprise. It is not a new business operator, private-state store, native account, evidence issuer, release path, invention engine, or physical controller.

## 1. Wheel topology

- **Hub: Transformational Intelligence.** Fixed owner-authorized purpose; revisable means; WORLD / POLICY / PROOF / AUTHORITY separated. Select direct specialist, qualified reuse, bounded composition, construct an instrument, abstain, or stop.
- **Inner wheel, commerce:** Offer → Deliver → Collect → Reinvest → Offer. Independent metric: accepted complete work, protected collections, complete-cost profit and available earned-funded continuation in **its stated simulated or observed scope**.
- **Middle wheel, invention:** Discovery → Synthesis → Reflection → Inheritance → Discovery. Independent metric: verified executable mechanisms, additional fresh successor benefit, and—separately—improved discovery policy across fresh matched work.
- **Outer wheel, production:** Bottleneck → Instrument → Measurement → Replication → Bottleneck. Independent metric: net useful, independently measured, replicable physical productive capacity.

These are three **closed rotations**, not a compulsory twelve-step linear pipeline. A commercial order does not need a new invention. A useful invention does not need a paying customer. No research-only result creates physical operating authority.

**Physical-flywheel analogy:** drive = genuinely created accepted value / verified capabilities; inertia = durable native history and reusable instruments; friction = all real costs, failures, maintenance and liabilities; bearing and governor = source-bound independent proof, risk limits, and explicit permissions. The metaphor must not imply perpetual motion or guaranteed exponential growth.

## 2. Native evidence boundary and source identity

`connected_enterprise/` is the **only canonical commercial runtime**. `adaptive_enterprise/account.py` through `connected_enterprise/finance.py` owns all account balances, liabilities, earned funding and source-bound recovery. This package does not implement a second financial state machine or action queue.

For a completed existing native enterprise, the readout calls **the original frozen-source** `python3 -m connected_enterprise audit --output <same original enterprise>` and then `scoreboard --output ...`. The auditor recomputes service artifacts, account financial semantics, registered worlds, report and completion identities. The scoreboard is read-only and must match the rederived audit on source identity, freeze ID, worlds and report digest. The auditor may refresh `PACKAGE_AUDIT.json`, but the wheel does **not** open or spend from the native account.

The wheel refuses to elevate unmeasured or historical conditions into facts: no real customer or revenue claim from simulation, no arbitrary cost/profit pooling of independent worlds, no annualization from short horizons, no invention or physical breakthrough from a financial audit. If a claim is outside the native auditor, it remains `NOT_ESTABLISHED_BY_NATIVE_COMMERCIAL_AUDIT` regardless of user-supplied enthusiasm.

The wheel never inherits current proof or authority. A stale research capsule is not an operating grant.

## 3. Run without any business data

From the project root, Python 3.12 or higher, standard library only:

```sh
python3 -m unittest discover -s tests -p 'test_flywheel_wheel_030.py' -v
python3 -m flywheel_wheel architecture --output /absolute/new/flywheel-wheel-030
```

Open `/absolute/new/flywheel-wheel-030/index.html` in a browser. It contains a circular three-ring SVG and an accessible, readable table with **unknown** claims, not fabricated financial performance. The output directory is create-only. Never reuse an existing path.

## 4. Bind it to a *completed*, **trusted** existing enterprise

Only operators with an explicitly trusted frozen source, original output and existing permission to run the canonical audit should invoke this route:

```sh
python3 -m flywheel_wheel audit-render \
  --enterprise /absolute/existing/native-enterprise \
  --output /absolute/new/wheel-audit-view \
  --audit-timeout 600
```

- The enterprise input must have `source/`, `FROZEN.json`, `REPORT.json` and `COMPLETE.json`. The frozen source is executable Python; **do not invoke untrusted extracted source**, even in an otherwise read-only display workflow.
- The canonical auditor is run first, and its accepted receipt is checked; then the matching scoreboard is retrieved. Any mismatch or unsupported assertion fails closed.
- A paused enterprise must be resumed via the **existing authorized native** run/resume procedure before a completed-run claim is possible. The wheel does not resume or reseed it and does not repair source-transition or financial-account authority.
- No customer outreach, paid model, live payment, token call, wallet approval, physical actuator, CI schedule, production release, or capital commitment is created by either mode.
- Output is `wheel.svg`, `snapshot.json` and `index.html`. The snapshot carries `funding_authority: false`. Its hash is for presentation identity, not independent certification or financial signatures.

If the canonical audit fails, the wheel does not publish a success display. If a valid completed report has no settled work, its commerce Collect stage remains *not observed* rather than showing a success from the presence of code.

## 7. Assurance, failure and qualification

- Every output remains historical and scope-bound, with failure records preserved.
- No candidate edits the evaluator or uses an old proof as a new permission.
- Positive accounting profit does **not** confer investable liquidity. Only the canonical account determines available unrestricted earnings at commitment time.
- The wheel is not a persistent scheduler or a recovery agent. Existing authorized hourly automation and source-bound operating commands keep their established responsibilities.
- CI only checks the visual and evidence-display contract. It does **not** qualify native release, financial migration, real commerce or physical operation. Normal repository qualification and released-archive download/operation evidence are separate gates.
- This feature is additive: no existing file in `connected_enterprise`, `adaptive_enterprise`, `commercial`, `mechanism_harness`, or their existing tests and historical evidence is modified.

**Stopping and promotion:** Retain the incumbent until source-exact qualification supports a concrete net useful gain over the strongest direct method. Unproved enabling value remains a research hypothesis. Invention and productive expansion are explicitly `NOT_ESTABLISHED` under the native commercial auditor.
