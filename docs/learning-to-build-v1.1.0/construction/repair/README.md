# One attempted raw-input foreground repair

**Outcome: the fixed composition failed calibration and was stopped.** It did
not advance to test scoring. The original results remain unchanged.

## Why this candidate was constructed

The exposed four-field component diagnostic in `../diagnostics/` showed that
replacing r12's foreground with the reference foreground raised boundary F1
from 0.250398 to 0.615828. Replacing nuclei alone worsened it. That suggested a
specific missing means: obtain a sufficiently useful foreground from measured
channels, without reference annotations.

The existing fixed CellposeDINO specialist already produces whole-cell masks
from those measured channels. We therefore implemented **one ordinary
composition**: use the union of its final, border-excluded masks as foreground
for unchanged r12 DNA-derived seeds and watershed. This candidate was supplied
by the assistant after interpreting the diagnostic. It was not generated by the
six finite constructor policies and is not evidence that they learned a new
construction method.

`PREREGISTRATION.json` was frozen at **2026-11-08 00:15:43 UTC**, before any new
composition scores. It binds both programs, diagnostic motivation, original
producer/checker source, numerical criteria, all input identities, existing
specialist masks and cost receipts, and the exact frozen model configuration.
`FREEZE.json` records the bytes. No new candidate parameter, foreground variant
or model was selected after evaluation.

## Actual prediction path

The single prediction function is:

```python
instrument.segment_cells(
    dna,
    actin,
    instrument.RECIPE_MAP["r12"],
    nucleus_labels=None,
    foreground_override=specialist_labels > 0,
)
```

`specialist_labels` means the final **post-border-exclusion** masks from the
exact registered `cpdino-vitb` whole-cell operator. No dilation, hole filling,
pre-border substitution or manual reference enters this composition. Its DNA
seeding, watershed and final complete-in-frame rule are unchanged r12 code.

The first evaluation used the four **already executed and hash-bound**
specialist calibration outputs as an explicitly cached constituent. It then
executed the composition, wrote all four new masks, and scored them using both
the original metric implementation and `check.score`. Each constituent mask was
also independently rescored and matched to its original field receipt and
source identities before use. All checks agreed.

This is actual composition execution with a cached constituent, **not** a new
execution of neural inference. The constituent's earlier nonzero cost is
attributed below. Manual references enter the evaluator only.

## Reproduce the negative result

Use the same classical numeric environment as `../diagnostics/README.md`:
Python 3.12.14, NumPy 2.3.5, SciPy 1.17.0, scikit-image 0.25.2 and Pillow 13.0.0.
Acquire the pinned public data and extract the main evidence archive using
`python evidence.py --extract NEW_DIRECTORY`, as described in `../README.md`.

From the `construction` directory:

```sh
python repair/evaluate.py \
  --cache /absolute/path/to/data-cache \
  --incumbent /absolute/path/to/extracted-evidence/incumbent \
  --output /absolute/new/composition-replay \
  --verify \
  --expected repair/RESULTS.json
```

Expected output is `status: COMPLETED_NEGATIVE_CALIBRATION_STOP`,
`calibration_qualified: false`, `test_fields_scored: 0`, and
`expected_numerical_endpoints_verified: true`. A successfully reproduced
negative result exits normally. An identity, runtime, score or source mismatch
fails and retains `FAILURE.json` and process costs.

IDs and hashes are exact endpoints. Numeric comparisons use relative tolerance
`1e-10` and absolute tolerance `1e-12`. New timing is retained separately and
does not have to equal the original. Every invocation requires a new output
directory. `OBSERVED_RUN.tar.gz` contains the complete first attempt's eight
files: four masks, the metrics CSV, invocation, results and process-cost receipt.
`EVIDENCE.json` binds that archive and the loose source/results files.

It invokes unchanged `incumbent.py operate --task cells`, which enforces the

scientific acceptance on supplied images, and no commercial rights are added.
