# ALPHA GENESIS FLYWHEEL Ω — Native enterprise execution 002

**See the frontier. Discover the consequences. Earn the right to improve the machinery.**

This additive engineering increment connects finite economic selection to **actual executable production on synthetic inputs**, independent acceptance, the repository's authoritative simulated financial accounts, and earned-funded successor research. It continues the direction of PR #229 without editing that PR's files, historical experiments, existing accounts, or the canonical money engine.

It is **supporting execution infrastructure, not the Blue Sky flagship**. The scientific and commercial flagship still needs a consequential new capability and genuine beneficiary evidence. Routine reconciliation and KPI fixtures are integration controls, not inventions of new industries.

## What this build does

1. **See the frontier:** `python -m genesis002.frontier` reads public release metadata from an explicitly named GitHub repository. It generates a source-bound request for a separately authorized frontier agent to propose materially different possibilities. Metadata remains `UNVERIFIED` access and `NOT_DEMONSTRATED` capability. No language model is called, source text cannot authorize actions, and no continuous monitor is installed.
2. **See the consequences and execute:** the registered finite scenario compares qualified conventional, generated and inherited methods with each buyer's outside option. It chooses a posted price and method, checks available cash, produces the actual artifact, independently checks it, and releases or refunds the order through **JournalAccount → adaptive Account**. No second financial ledger exists.
3. **Test an improvement:** when the declared research option value exceeds its cost and current native earnings can pay, the operator funds a router-selection study. A policy is selected on one synthetic partition, frozen, and evaluated on a distinct synthetic partition against a strong direct conventional constructor. A tie retains the conventional method. This does not claim general learned discovery or autonomous strategy invention.

## Run inside the repository

Use a supported local Linux/POSIX filesystem and the repository's existing Python/dependency environment. Never upload a private output directory. Its native state includes local simulation signing and recovery material.

```sh
# Inspect the finite economic admission screen without starting an account.
python3 -m genesis002 plan \
  --config campaign/genesis-enterprise-002/INPUT.json

# One new, separately registered simulation. Choose an output that does not exist.
python3 -m genesis002 run \
  --config campaign/genesis-enterprise-002/INPUT.json \
  --output /absolute/new/genesis-business

python3 -m genesis002 audit --output /absolute/new/genesis-business
python3 -m genesis002 resume --output /absolute/new/genesis-business
# Open /absolute/new/genesis-business/OPEN_ME.html
```

`--repo /path/to/exact/native/source` supports a separate declared canonical checkout. Imported native modules must come from that checkout; a mixed-source process is refused. The default is the repository containing `genesis002`.

The example uses **US$500 simulated opening capital** and US$25 working reserve. These are an explicit new experiment, not an enterprise floor, ceiling or change to earlier $100,000 accounts. The primary continuation policy is `EARNED_ONLY`: the first operating cycle may use opening capital, later operating expenditure must use native unrestricted earnings. `AVAILABLE_NATIVE_CASH` is a separately declared alternative using existing permitted cash, not a reseed or forecast-funded top-up. Neither policy removes the native engine's permanent principal/fee protection obligations.

The startup screen declines a declared route whose optimistic full-horizon margin cannot recover its fixed setup/discovery cost. Passing that bound admits qualification, not real demand. A learning experiment is declined when its declared prospective benefit does not justify its cost. Expected research option value never becomes money.

## Pause, interruption, and recovery

```sh
python3 -m genesis002 run \
  --config campaign/genesis-enterprise-002/INPUT.json \
  --output /absolute/new/checkpointed-genesis --max-cycles 1
python3 -m genesis002 resume --output /absolute/new/checkpointed-genesis
```

A pause retains the original funded account. Each episode's decision is bound to its actual pre-action native prefix. Idempotent native action identifiers recover a committed acquisition/production without duplicate spending. The tested interruption occurs after production funding is committed and before artifact completion. Missing key, tape or journal causes refusal, not reseeding. Changed configuration, source or stress also causes refusal. A completed account with an additional later expense is stale and cannot silently continue under its old report.

Pre-account bootstrap is separate: an interrupted partially written `bootstrap/` or unsealed `runtime/` requires inspection; the operator does not guess ownership or delete it. Recovery testing is not proof against every possible crash or filesystem failure. Use the native ownership mechanism and preserve the entire original directory privately.

## Independent negative runs

```sh
python3 -m genesis002 run --config campaign/genesis-enterprise-002/INPUT.json \
  --stress no_demand --output /absolute/new/genesis-no-demand
python3 -m genesis002 run --config campaign/genesis-enterprise-002/INPUT.json \
  --stress failed_acceptance --output /absolute/new/genesis-refund
python3 -m genesis002 run --config campaign/genesis-enterprise-002/INPUT.json \
  --stress payment_failure --output /absolute/new/genesis-no-payment
```

Each is a **separate fresh account**, never pooled with the primary. Stress is an adverse operating realization after startup has been committed under the original opportunity hypothesis. No-demand therefore preserves incurred setup/research losses; it does not erase them by retroactively refusing the startup. In contrast, the *ex ante* screen refuses an already-unattractive declared programme before creating any account.

## Evidence and ordinary controls

`REPORT.json` states hypothetical financial outcomes and zero actual revenue. `deliveries/` contains real executed artifacts and independent checks; `intents/` contains source-bound decisions. `NATIVE_EXPORT.json` is reconstructed by the existing native audit, then a separate operating audit checks prices, method selection, acceptance, resource charges, funds, order, taxes, research and exact reconciliation.

The legacy admitted-service schema settles against an existing source-bound reference artifact. The new actual-production record must independently satisfy acceptance and semantic equality with that reference. Its digest is additionally anchored in the native journal. This is **not** a newly implemented arbitrary late-bound-service schema.

All methods and prices are enumerated only within a registered finite set. The selector is exact for the declared one-order objective and cash envelope; it is not a multi-period global optimum, a learned demand model, an equilibrium proof or open-world opportunity discovery. Buyer preference ties decline. Failures count. Complete modeled costs include the listed setup, discovery, acquisition, production, checking, support, integration, maintenance, payment fees and declared tax provision; actual host/model/development bills and real acquisition costs remain unknown.

The study's learned router ties strong conventional pruning. The generated comparison performs more counted mapping work. **Do not advertise the generated comparison as the strongest baseline, a wall-clock speedup, an improved inventor or a proprietary advantage.** The positive system behavior is selecting and retaining the better available established method.
