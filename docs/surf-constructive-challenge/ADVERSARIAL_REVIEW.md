# Adversarial review — research edition 1.0.0

**Reviewer status:** the same assistant that drafted the manuscript performed this review. Separate code implementations are present; a separate frontier LLM or independent institution was not invoked. This record is not external peer review.

## Challenges, decisions and changes

1. **The book-summary insight was already in the foundation.** Upheld. The manuscript explicitly credits *Transformational Intelligence* §1 and Appendix C. Its additional contribution is a constructive link to missing means, economics and successor attribution.
2. **A critic could fabricate an omission.** Upheld as an implementation concern. The adjudicator now compares the cited source item with the actual presented output, not the critic's self-reported `present` flag. Tests reject an invented omission and retain a real omission despite a contrary flag. Source labels are still authored, not semantic natural-book judgments.
3. **The capacity repair might be an unnecessary invention.** Upheld for the added supplier-failure/high-price case. The first development expectation was 22; both implementations returned 17 because the direct P+R route avoids the affected supplier. The expectation, not the result, was corrected. That ordinary winner remains a named control.
4. **Modeled profitability was inserted into the inputs.** True of any actual-market interpretation. Costs, prices, supplier acceptance, scenarios and capability deltas are supplied. Actual receipts remain zero. The study supports conditional computation, not demand, contracts or real profit.
5. **The full conventional oracle ties.** Upheld and reported. The constructor is not claimed superior to existing optimization. Its purpose is an executable witness of composition and joint feasibility.
6. **The scenario set might omit the decisive disruption.** Upheld as a scope boundary. The finite guarantee covers only declared scenarios. The paper states information/nonanticipativity assumptions and a prospective external scenario-acquisition test.
7. **The financial path could be mistaken for the existing operating ledger.** Prevented explicitly. `financial_path` is an analytical conditional path, not a native account. No existing account, signer, private recovery state, or authorization was opened or changed.
8. **Repeated tests might be called fresh discovery evidence.** Prevented. The exact model is an authored development/verification study. The paper separately proposes fresh complete-campaign comparisons for discovery improvement.
9. **A build or hash proves the scientific claim.** Rejected. Byte identity and syntax checks have separate, narrow meanings. The claim–evidence register names each boundary.
