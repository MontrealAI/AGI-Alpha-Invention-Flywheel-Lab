# Execution resources are not simulated business costs

Current engineering, qualification, publication and released-source operations use the actual execution platform window. They do not impose a separate 20-, 30- or 45-minute mission ceiling. Standard GitHub-hosted jobs retain GitHub's six-hour hard maximum; elapsed setup and a five-minute receipt/shutdown reserve are included. ChatGPT Pro does not supply or extend that GitHub limit. Standalone included-tool work must not invent a universal mission deadline from a hosted-runner rule.

For current engineering and downloaded-release operations, measured CPU is telemetry, not an invented business budget. Historical frozen workers, registered experiments and their original resource verdicts remain source-bound. A former limit failure stays a failure under its original scope; new authority does not retroactively qualify it.

The fixed six-command run/resume/audit/package/audit/audit protocol and all source, privacy, financial, and audit checks remain. Commands do not retry automatically. A genuinely interrupted operation retains its failure and recovery state. Subsequent work resumes where supported or is labeled a separate reproduction. Work longer than one actual platform window needs resumable decomposition, not a false pass, an invented unlimited runner or paid capacity.

CPU (including waited children) and wall time remain recorded. A command failure, deadline interruption, changed source, changed balances, rejected audit, or private archive still fails. Historical and realistically modeled business costs are not rewritten; measured billing and unknown billing remain distinct.

Use included ChatGPT/Codex capabilities and standard `ubuntu-latest` public-repository compute only. No paid model APIs, model API keys, billing activation, larger/GPU runners, custom images, private paid compute or new paid services are authorized. Standard public GitHub runner compute is free under GitHub's policy, separately from ChatGPT Pro. Account storage/billing is not an audited zero-cost entitlement; this change authorizes no overage or billing-setting changes. References: [GitHub billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), [hosted runner limits](https://docs.github.com/en/actions/reference/limits).

Candidate generation, money, buyers, services and profit have no arbitrary universal ceiling. Preserve actual native cash, obligations, supplier contracts, acceptance, security and computational-input safeguards. Use exact arithmetic and batching/streaming for scale; a finite declared workload or an actual checkpoint is not a business-scale maximum. The US$3 billion objective remains unachieved and does not grant new spending authority.
