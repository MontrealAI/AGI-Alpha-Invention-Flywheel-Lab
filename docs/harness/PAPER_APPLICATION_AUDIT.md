## Decision

**The papers are not all operationally implemented or enforced.** Some mechanisms are real and source-bound, some are standalone exact research examples, and others remain guidance. Correct application requires selecting an applicable mechanism and testing its actual effect. Forcing every named method into every run can be less effective than a simpler conventional route. Global optimal use has not been established.

- Eight entries have related partial runtime mechanisms: native current-cash protection, independently rederived finite strategic decisions, bounded criticism/reframing, source-bound inheritance and categorical reflection. Their scope is narrower than the papers, and related machinery is not proof that the complete paper was implemented.
- Three newest companions are standalone: SUPER ALPHA's ordered-prefix funding/deadline screens, OUT-ACCELERATE's costed policy comparison and FLYWHEEL 1.1's typed instrument constructor.
- Seven entries remain guidance in the inspected canonical path: The World as an Output, Foundry v2, OUT-LEARN, OUT-THINK, OUT-DESIGN, OUT-STRATEGISE and OUT-EXECUTE. This is not a claim that no related experimental code exists anywhere or that every method is relevant to the current task.
- The original FLYWHEEL 1.0 remains historical. The November 2 report synthesizes prior evidence; it is not a runtime mechanism or a newly executed pooled experiment.

## The immediate operational repair

The original PR191 seller is honestly a fixed-cost research comparison. `omega/seller.py` fixes US$100,000, charges an authored US$24,800 schedule and sets native sales to zero. Its replay prevents fabricated reports; it does not choose capital, avoid unnecessary work, stage information acquisition, construct a sale, set prices, react to demand, stop or pivot. A negative fixed-policy result does not prove that all strategic arrangements lose money.

A separate prospective seller experiment should use the existing native account and preserve that frozen arm. Required behaviors come from applicable mechanisms, not a mandatory paper-reading ceremony:

1. **Invent the Economy / SUPER ALPHA:** compare non-entry, staging and complete product arrangements with explicit voluntary outside options; distinguish receipts, profit, commitments and available funds. Model full production/support/refund/financing costs and disclose uncertain costs.
2. **OUT-STRATEGISE:** define permitted observations and pay for information before its result is revealed. At each information set the same executable action must apply to every compatible world. Comparing separate clairvoyant world optima is not an implementable policy. Compare a robust no-test route as well as information-gathering routes.
3. **SUPER ALPHA / Beyond the Production Frontier:** check every cash prefix, reserve and obligation, funding timing, qualification delay and any relevant advantage deadline. The existing `JournalAccount.spend` already protects present native cash; new plan screens must not create a second ledger or spend forecast receipts.
4. **OUT-EVOLVE / FLYWHEEL:** freeze assets before fresh successor work; compare removal, equal-content ordinary reuse and unrestricted competent construction with all acquisition/verification costs. A useful tool and an improved inventor are separate claims.
5. **OUT-ACCELERATE:** measure the complete route to accepted output. The supplied ordinary workflow ties the best accelerator. In the FLYWHEEL foundry, the ordinary constructor uses 13,566 scalar arithmetic operations versus 48,141 for accumulating reuse. Preserve these results; do not force the named method or equate operation counts with dollars.

Any later strategy/product extension requires separate source-matched review. This audit does not adopt, qualify or claim completion of later source. Physical qualification and actual demand remain separate from realistic native simulation.

## What already rejects real violations

- `connected_enterprise.finance.JournalAccount.spend`: native snapshot, available-fund admission, earned-versus-seed distinctions and source/state-bound commitments. No inferred absence merely because a newer paper companion is not imported.
- `connected_enterprise.strategic_audit.audit_decisions`: reconstructs decision inputs from the actual ledger prefix, current public observations, operating deductions and registered policy; rederives selected effects.
- `mechanisms.memory`: rejects changed source/dependencies and keeps current proof/authority distinct from retained procedures.
- `mechanisms.criticism.adjudicate`: requires reproduced objections before repair. `instrument_spec` explicitly constructs a specification, not an instrument.
- `mechanism_harness.evidence.reflect`: conditional categorical recovery under a declared source-group fault bound. It is not OUT-REFLECT's polynomial moment-code construction and cannot prove source independence.

These are substantive guards. They do not enforce open-world relevance, physical truth, realistic prices, autonomous discovery or universal strategic optimality.

## Executed checks and limits

On the audited source, SUPER ALPHA's 14 unit cases passed; OUT-ACCELERATE's seven-policy check regenerated byte-identical JSON/CSV; the FLYWHEEL instrument foundry replay matched source/protocol-bound scientific fields. Existing publication CI already invokes these companion checks. The new 15-case maintenance suite, 16 existing website tests and 64 existing construction/criticism/memory/composition tests also passed locally. These finite studies and focused tests retain their own assumptions and strong controls; they are not a whole-repository pass or operational adoption evidence.

The new maintenance check runs with `python scripts/check_paper_applications.py` and is covered by `test_paper_applications.py`, which the existing all-PR Connected 014 workflow invokes explicitly before its runtime suite. Existing release qualification also invokes it on PRs and main pushes, so combined changes with stale reviewed identities cannot silently proceed to a release. This maintenance-only test is outside the runtime export glob, so it does not introduce incomplete paper dependencies into released native account packages. It rejects omitted/duplicate publications, changed editions, stale reviewed source bytes, invented symbols, citation-only implementation entries, absent scope/gaps and unsupported qualification/optimality status. The edition check compares declarations against the publication manifest; the existing website tests separately hash actual PDF bytes. Referenced-file hashes do not cover unlisted transitive dependencies. Its output deliberately says **traceability only**. It does not execute the referenced tests, prove that a caller uses a method, validate an author's applicability judgment or grant authority. Required-check settings are not changed or claimed.

When a referenced source or paper changes, examine the semantic impact and rerun relevant independent checks before updating its recorded hash. Never refresh hashes just to make CI green. Add new publications with an honest status and a concrete adoption decision; do not mark all entries implemented to satisfy coverage.
