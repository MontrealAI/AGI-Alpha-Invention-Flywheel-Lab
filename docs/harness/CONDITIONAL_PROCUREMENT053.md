# Conditional procurement 053: opt-in, finite local comparison

This additive experiment composes three existing independently checked outcomes:
reconciliation, KPI variance, and an evidence matrix, delivered as one native
`operations_bundle`. Component work identities cannot also be sold independently.
It does not contact suppliers or customers and grants no real spending authority.

## What is compared

`connected_enterprise/conditional_procurement053.py` translates observed local
quotes into the existing finite `mechanism_harness.core.compose` grammar. The
separate ordinary enumerator considers every potentially optimal supplier subset,
including an integrated provider. Both receive identical inputs, prices,
availability, expiry, budget, assembly cost, and scenario disclosures. Both rank
by **total cost, number of selected quotes, then sorted quote identifiers**.
Positive-cost redundancy cannot improve a complete three-service cover.
Available quotes whose own price plus assembly cannot fit the current budget are
excluded from grammar construction, not rejected as observations. Budgets beyond
the grammar's integer representation use an explicitly labeled `ordinary_fallback`
route with the unchanged exact budget and ordinary verifier; no silent cash cap or
symbolic-invention claim is made for that route.

A symbolic plan is not delivery: every selected component is freshly executed
through its existing adapter and the complete output passes `audit_bundle`.
Provider default is a declared adverse scenario, not a prediction or evidence of
a real agreement. An incomplete bundle produces no invented accepted sale or
refund. Ordinary selection can tie or win; neither outcome is evidence of
machine-discovered invention or an advantage over competent ordinary commerce.

## Reproduce and verify

Use Python 3.12 and an otherwise qualified checkout. The focused modules use the
standard library directly; the reused native engine requires the repository's pinned
cryptography dependencies. No model API, paid service, or credential is required:

```sh
python -m pip install -r requirements-commercial010.txt
python -m unittest discover -s tests -p 'test_packet_geometry051.py' -v
python -m unittest discover -s tests -p 'test_procurement053.py' -v
python -m unittest discover -s tests -p 'test_native_procurement053.py' -v
python -m unittest discover -s tests -p 'test_procurement_source053.py' -v
python scripts/run_conditional_procurement053.py --help
```

The path-scoped pull-request and manual `conditional-procurement053.yml` workflow
runs exactly these four modules in disposable test fixtures. Runtime adoption
remains opt-in. It neither overlaps a campaign execution nor uploads private account or
recovery state. A workflow file is not a workflow success receipt.

For an explicitly selected finite comparison, use a new absolute output path:

```sh
python scripts/run_conditional_procurement053.py --output /absolute/new/private-run
```

This creates new private native recovery state. **Do not upload the output tree**
or signing/recovery files. The native test module already executes all ten
case/policy combinations in disposable accounts; another run is not required to
claim that test coverage. Separate runs have separate seed allocations and are
not continuation or migration of any existing account.

The canonical connected runner explicitly includes the optional module's full
script/protocol/checker/test/document/workflow closure when present. Missing
members fail before freezing. With the module absent, the legacy inventory path
is unchanged. Source tests separately cover isolated inventory logic and a real
freeze, ZIP extraction, exact identity comparison, and extracted runner import
and help invocation; the latter creates no accounts.

The optional per-job packet row vector is versioned admission v2; legacy scalar
admission stays v1. This is a workload-shape capability, not greater demand or a
commercial result. No existing account is migrated or reseeded by this change.

## Economic and evidentiary limits

`campaign/conditional-procurement-053/PROTOCOL.json` freezes the authored costs,
participation alternatives and five scenarios. Native accounts are separate;
seed and earnings are never pooled. Revenue, collections, protected obligations,
and full modeled costs must remain on the canonical financial history.
Local quotes, buyer utility and provider availability are assumptions—not actual
consent, market observations or real revenue. Actual engineering/model/host costs
remain unknown beyond stated modeled envelopes. Source tests and bounded native
comparisons do not establish general invention, retained discovery advantage,
causal capability enabling, annual scale, or a grand business breakthrough.
Publication, integration and release qualification remain separate owner steps.
