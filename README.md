# AGI ALPHA — Invention Flywheel Lab

**Blue Sky · Beyond-Human Foresight · Transformational Intelligence**

**Commercial flywheel objective:** verified invention → accepted valuable delivery → complete-cost surplus and unrestricted earned resources → new construction → fresh successor benefit.

Build an invention enterprise whose useful work expands what it can discover and construct next. Start with an important productive outcome that is unavailable or uneconomic under strong competent alternatives. Then invent the missing means—not a business justification for a convenient existing demo.

## The smallest useful loop

Opportunity discovery → cross-domain structural mapping → executable adaptation / strategy invention → decisive adversarial verification → retain supported mechanisms **and failed transfers** → test a fresh successor.

The methods themselves remain revisable. An ordinary solver, a simpler representation, or stopping can beat a more elaborate agent arrangement. A repository of remembered artifacts is not evidence of learning.

## Status and quickstart

This first slice is a standard-library-only **infrastructure experiment**, not an admitted Blue Sky opportunity, live model benchmark, physical validation, commercial success, or proof of self-improvement. No model API, credentials, spending, outreach, real transactions, or arbitrary generated code execution is required.

See `PROTOCOL.md` for the admission and confirmation boundary; `opportunities/grid-interconnection.md` is an evidence-backed research question, deliberately **not admitted** and not represented by the bootstrap fixture.

Python 3.10+; no third-party packages:

```sh
python3 -m unittest discover -s tests -v
python3 lab.py screen examples/opportunity.json
python3 lab.py demo --output runs/first
```

Run from the repository root. Choose a new output directory for each attempt: rerunning `runs/first` fails rather than replacing failures. The demo tests a queue-ordering mechanism transferred to synthetic serial checks, using an exhaustive independent implementation as the mathematical checker. Its cases and checker are public, not a separately controlled verifier service. It retains one failed transfer and one fixture-scoped valid policy. The inherited policy **ties competent ordinary controls** on the successor; no successor gain is established. Runtime bounds are 2 registered candidates, at most 16 cases per evaluation, at most 7 jobs per case, and durations 1–100. There are no arbitrary plugins or generated-code execution paths.

Opportunity screening checks record shape only; it never grants admission. Edit the opportunity record and fill evidence gaps before proposing a real experiment. To add a trusted registered experiment, change code and tests in a reviewed PR; keep the original run evidence.

## What is implemented—and what remains research

The current kernel executes registered policies, verifies them with an exhaustive checker, preserves counterexamples and fixture-scoped successes, and runs matched successor controls. Structural mappings are manually supplied; policy enumeration is not runtime strategy invention. Opportunity screening validates JSON shape, not autonomous discovery or admission. The small fixture is plumbing, not a replacement for recovered SUCCESSOR Ω or a claim that ordinary queue scheduling is an invention.

Next experiments must earn actual structural discovery, constructed executable adaptations, independently protected confirmation, and causal successor benefit. Complete costs remain unknown; `human_work` is an accounting category for actual evidenced human effort, not invented agency labor or a charge fabricated from model activity.

## Three separate verdicts

1. **Works in declared scope:** an independently checked executable adaptation meets the frozen outcome.
2. **Economically viable under declared conditions:** same cohort and complete alternative; all lifecycle costs, quality, risk, and horizon included. Unknown costs are unknown, not zero. Simulation is not revenue.
3. **Causally helps a fresh successor:** inheritance beats no-inheritance and ordinary-reuse controls at matched complete resources on fresh problems. A fast final run alone is insufficient.

Passing one never implies another. Bootstrap checks are developer-visible and cannot certify independent research claims.
