# Independent OS-kill-after-native-commit CAS qualification — frozen protocol

**Scope:** additional engineering-only P0 adversarial test on one newly created, ephemeral simulated financial account. This is not the inaccessible completion023 signer, an operating-queue migration, semantic current-main composition, a production service, a whole-source certification, or a release.

**Source discipline:** run only on the pinned independent PR #295 source lineage; require this entire protocol to be byte-identical to this preregistration commit before execution. Keep existing HMAC verification, evidence limits, account ownership, source identity, journal recovery and archival resource guards unchanged. Failed executions stay failed. The test source and workflow may be added only after this protocol is committed.

**Failure model and test (one fixed case, no seed selection):**

1. Create one ordinary same-path native `JournalAccount` with prospective order, nonempty financial action tape, 20,000,000 microUSD covered claim and unpaid claim obligation at the protected maturity boundary, using the existing `test_completion024_cas_claim_boundary_independent` fixture. Snapshot exact original actions, balances, prospective claims/payables, signing-key inode, and original signed journal; obtain one valid owner-authorized v2-CAS transition ticket to a different source. Keep simulated HMAC material private; never include account files or signed ticket in outputs or uploaded artifacts.
2. Independently validate the ticket with the actual local simulated owner key, exact account path and source. Start an isolated child OS process at that exact account path and input the ticket only on stdin. Child opens the canonical `JournalAccount.upgrade_source` under the existing explicit evidence directory. Monkeypatch only the child process's `adaptive_enterprise.account.Account.source_transition` wrapper so it calls the real method once and then raises process-fatal `SIGKILL` immediately after that native call returns, before `JournalAccount` can finish its connected-journal recovery sequence. No fake journal writes or process-internal exception substitutes.
3. Require child termination by `SIGKILL`, not a normal exit or ordinary exception, and a private-free fixed marker emitted after the native call. Reopen the same account with exactly the same authenticated ticket and evidence directory. The canonical built-in recovery must complete (or the test FAILS, with no relaxation). Independently reopen without an upgrade ticket after recovery. Require accepted native/connected audits, precisely one source-transition action, **byte/equality-preserved original financial action prefix**, same prospective claim and outstanding payables, unchanged original key inode, no new collection, and identical new-source exported records across recovered and ordinary reopen. Reject attempted source downgrade to original source without financial mutation.
4. If interrupted recovery cannot finish safely, fail the test; do not initialize a new account, import/copied money, clear obligations, manually edit JSON/SQLite, weaken guards, replace the verifier, or change source semantics. Never print child stderr, private paths, signer bytes, account files, or unredacted tickets in hosted logs. Cleanup ephemeral account data without publishing it.
5. Report fixed case count, exact commit/test/protocol hashes, measured resources, exit code/status, and the strict **PASS/FAIL**. Passing this single crash schedule is not all-write-ahead boundaries, all concurrent writers, long-horizon continuity, main composition, original-account handoff or commerce.

**Decision:** even if this exact test passes, retain P0 NO-GO until the sole integration owner reconciles the full current-main finance/source union, qualifies fresh source-matched publication, obtains valid original signed-account custody/lease and publishes/independently downloads a normally merged release. US$3B trailing-365 modeled-cost profit is unchanged/unqualified.
