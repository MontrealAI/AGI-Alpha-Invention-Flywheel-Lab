# FRONTIER Ω ALPHA · Public Atlas operations

The public Pages workflow takes editorial records from the reviewed main history and reference signals from `publication/frontier-watch-refs.json` on `frontier-watch-public`. Each path has a pinned first-parent starting revision. The branch's ordinary forward commits retain sources after the watch selection rotates. The consumer validates bounded public inputs, reapplies topic holds across automatic history and checks new titles, exact versions and source dates at their publishers. It records a digest of each primary metadata response. An earlier published metadata result can be reused only when its exact Git receipt, source version and date still match. The old, explicitly reviewed AnyS1 editorial card is preserved as a dated preprint lead. The hold continues to exclude automatic transfer and rendering from the watch inbox.

The hourly ChatGPT publisher can write only version-pinned public references to the one approved inbox file under the existing scope. Monitor text, private task identifiers, findings prose and access credentials stay in ChatGPT. New external references enter the Atlas as discoveries. Proposals and author reports carry no experimental or economic acceptance. The reviewed editorial file can record a different state when it has appropriate pinned evidence. The browser remains usable without a wallet or JavaScript. The browser search matches titles, content and historical versions.

The read-only build checks inputs, rebuilds both languages and compares the deterministic artifact against the live projection. The deployment job alone has Pages and OIDC write permissions. A separate read-only job fetches the published ledger and both public HTML pages. After a change it also exercises the website in Chrome using isolated wallet-provider test data. The funded scope is the existing public runner and Pages deployment. The browser test does not call Ethereum, request a signature from a participant or send a transaction.

## Recovery and release evidence

- Read [Pages workflow runs](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/actions/workflows/research-pages.yml) for individual outcomes, accepted input counts and validation failures. The public [release receipt](https://montrealai.github.io/AGI-Alpha-Invention-Flywheel-Lab/frontier-omega-alpha/atlas-release.json) records the latest deployed source, last content change, and ledger hash. An unchanged successful check does not change the public timestamp.
- Invalid inputs stay excluded. A failed source read is retried on a later scheduled run. A rebuilt Pages artifact uses a distinct attempt name. The deploy job reads the exact build output, including on a deploy-only retry. A previous validated record is retained across quiet cycles. If Git history is unavailable, no longer includes its pinned start, or drops a previously published intake commit, the release stops and the last successful site continues serving. Do not force-push or reset either source history.
- Correct an input on its permitted branch using a forward commit. A withdrawal from automatic public output goes through the reviewed hold file, which applies across every version. After a website regression, revert the affected changes through the normal reviewed main pull request. Requalify and compare the actual public receipt and both URLs afterward. Keep the original failure in the workflow record.
