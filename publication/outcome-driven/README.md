# MY FRONTIER Ω · Local executor 1.2

Activate your full ambition in **My Frontier**, then use **Intelligence** to pair the browser with HARNESS on this device. Check an installed model to resume the recorded ambition. From **My Results** you can reopen the run, review proposals and tool receipts, and export the journal. Start the included `Launch-FRONTIER` launcher with Python 3.11 or later. Linux is the qualified connector environment. The local guide covers Ollama, LM Studio, llama.cpp, vLLM, and the optional reviewed ChatGPT or Codex handoff.

The **Mission outcome** displays conclusions generated from current verified tool receipts. If a required observation is missing, it identifies the missing field and row when the input has a declared primary key. Open **Model proposal for review** to see the model's interpretation. Qualified numerical claims and independent acceptance of a broader result are recorded separately. The result stays reviewable when verification has yet to be established.

### Operator input

Use `--mission-evidence /path/to/authorized-input.json` to associate an input contract with an exact ambition and language. Start from the existing [input examples](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/tree/main/publication/evidence-bound). The operator can supply these optional fields inside `requirements`.

| Field | Purpose |
| --- | --- |
| `approved_schemas` | Maps dataset IDs to approved SQL tables, field types, primary keys and optional measurement metadata. Matches the approved data before construction. |
| `outcome` | Specifies the deliverable and can state the criteria, assumptions, constraints, alternatives and verification method. Its `required_claims` must equal the registered claims. |
| `source_snapshots` | Pins authorized, previously acquired UTF-8 source bytes by ID, URL, version, content type and SHA-256. Explicitly enable `read_source_snapshot` in `tools`. The receipt records operator acquisition. Use `next_byte_offset` to inspect further excerpts. |

For a SQL constructor, supply `dataset` and a read-only query. The executor supplies the schema. Use textual fractions in the result column when exact ratios are required. For a formula instrument use `numeric_mode: "exact-rational"`, with integers or decimal and fraction strings. Tool receipts and journal provenance carry both the source and execution identities.

Refresh the local model check after a restart, then reopen the saved run from **My Results**. To restore a portable journal in a fresh workspace, launch with `--mission-model MODEL --mission-import /path/to/frontier-execution.json`. Reauthorize the input contract to resume evidence-bound work. Follow the shipped `docs/CHATGPT-PLAN.md` for official account activation and an exportable diagnostic receipt. Keep all private journals and authorizations on approved infrastructure. [Confidential delivery and independent custody](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/issues/565)

## MON FRONTIER Ω · Exécuteur local 1.2

Activez votre ambition dans **Mon Frontier**, puis ouvrez **Intelligence** pour jumeler le navigateur avec HARNESS sur cet appareil. Vérifiez un modèle installé pour reprendre l’ambition déjà enregistrée. Dans **Mes résultats**, vous pouvez rouvrir la mission, examiner les propositions et les traces d’exécution, puis exporter le journal. Lancez `Launch-FRONTIER` avec Python 3.11 ou une version ultérieure. Le connecteur a été qualifié sous Linux. Le guide local couvre Ollama, LM Studio, llama.cpp, vLLM et le transfert assisté vers ChatGPT ou Codex.

Le **Résultat de la mission** présente les conclusions tirées des traces d’exécution vérifiées. S’il manque une observation requise, il indique le champ et, si une clé primaire est déclarée, la ligne concernée. Ouvrez **Proposition du modèle à examiner** pour lire l’interprétation du modèle. Les mesures vérifiées et l’acceptation indépendante du résultat global font l’objet de contrôles distincts.

### Données autorisées

Utilisez `--mission-evidence /chemin/donnees-autorisees.json` pour rattacher un contrat à une ambition exacte et à sa langue. Les [exemples de fichiers](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/tree/main/publication/evidence-bound) servent de point de départ. Les champs suivants sont facultatifs dans `requirements`.

| Champ | Utilité |
| --- | --- |
| `approved_schemas` | Associe les jeux de données à leurs tables SQL, types, clés primaires et métadonnées de mesure. Le moteur vérifie la structure avant de construire l’instrument. |
| `outcome` | Précise le livrable, les critères, les hypothèses, les contraintes, les solutions concurrentes et la méthode de vérification. `required_claims` doit correspondre aux mesures déclarées. |
| `source_snapshots` | Déclare les fichiers UTF-8 autorisés, déjà acquis, avec leur URL, version, type et empreinte SHA-256. Activez `read_source_snapshot` dans `tools`. Le journal identifie l’acquisition par l’opérateur. Utilisez `next_byte_offset` pour lire les extraits suivants. |

Pour SQL, indiquez `dataset` et une requête en lecture seule. L’exécuteur fournit le schéma. Pour conserver un quotient exact, retournez une fraction textuelle. Dans une formule, `numeric_mode: "exact-rational"` accepte des entiers et des nombres décimaux ou fractions écrits sous forme de chaînes.

Après un redémarrage, reconnectez le modèle enregistré et retrouvez la mission dans **Mes résultats**. Pour restaurer une copie du journal, lancez `--mission-model MODÈLE --mission-import /chemin/frontier-execution.json`. Autorisez de nouveau le contrat de données pour poursuivre une mission fondée sur des preuves. Le fichier `docs/CHATGPT-PLAN.md` décrit l’activation officielle et l’export du diagnostic. Conservez les autorisations et journaux privés sur l’infrastructure approuvée. [Livraison confidentielle et conservation indépendante](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/issues/550)
