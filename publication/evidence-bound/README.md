# MY FRONTIER Ω

MY FRONTIER sends your full ambition to the HARNESS mission runner on your device. The runner records the approach, requests to your model, permitted tool operations, files, refusals and verification results. Reopen the same journal from **My Results** after a browser restart.

## Your local intelligence

1. In **Intelligence → Use intelligence on my computer**, download and extract the local executor. Open the `Launch-FRONTIER` file for Linux, macOS or Windows. The launcher needs Python 3.11 or newer. The Linux connector is exercised here. Native macOS and Windows setup remain unqualified.
2. Start a compatible model runtime on your device if you have one. The local guide links to the upstream installers for Ollama, LM Studio, llama.cpp and vLLM. For a custom llama.cpp or other OpenAI-compatible port, launch with `--config` and a locally reviewed configuration such as `local-model.example.json`. Review each upstream download and model license before installing.
3. Activate your ambition in **My Frontier**. Open **Configure intelligence**, pair this browser using the one-use code on your device, and select **Find local models**. Choose a discovered model and select **Check and use this model**. HARNESS sends a short local check. When it succeeds, MY FRONTIER resumes the ambition you already entered.
4. The executor remembers the selected local model in its private workspace. After restarting the connector, use **Reconnect my model** to verify the same selection again. In **My Results**, open **Save or reopen a mission** to recover a previous run. Review its history and resume under the current authorization.

When no model is ready, the connection status offers setup and reconnection. You can also review and export a manual intelligence mission. The prepared handoff is an assisted route. Model activity begins after you choose a local connection or submit the reviewed handoff yourself.

The local profile can prefer qualified deterministic tools inside the mission’s existing permissions. The model can use the same bounded dispatcher to interpret, construct and repair. The preference does not grant a new tool, trigger a network request or select a paid provider.

### Recovery and authorized evidence

The connected browser can pause, resume, cancel and download the mission journal. A connector or model interruption is recorded. A resumed mission must fit the current provider, model, tools, time and action limits. For a portable restore, start the launcher with the existing private configuration and `--mission-model MODEL --mission-import /path/to/frontier-execution.json`. Review the imported journal before resuming it. A portable checksum establishes file integrity only.

An operator can launch with `--mission-evidence /path/to/authorized-input.json`. The file is accepted only for the exact ambition and language it names. The public browser never supplies the file path or sets the claims, reference answers or tool permissions. The executor verifies source identity, data digest, lineage, dimensions, unit, tool, executed result and reference agreement. A mismatch or missing reference stays visible. Fictional, synthetic and simulation data cannot substantiate claims about a real input. [Replay of the historical mixture failure](claim-binding/REPLAY-RECEIPT.json)

## ChatGPT and Codex

Open the local HARNESS workbench to configure an eligible ChatGPT plan or the supported Codex integration. Review the permission shown by OpenAI before sending work. The connector records a completed request per account and route. A valid sign-in, access permission or model listing alone leaves execution unconfirmed. Consult the setup guide shipped with the archive for the optional verifier and native Codex sandbox check. The current study used a native Codex discovery probe and synthetic account protocol tests. Live account access and sandboxed construction remain unqualified. [ChatGPT and Codex guide](../../products/alpha-genesis-harness/docs/CHATGPT-PLAN.md)

## Authorized API access

Configure approved credentials in the local workbench. Verify the exact provider, project, model, credit balance and spending controls before execution. Where eligible, follow the official activation route for plan-linked API credits, then verify the usage and credit entry in that API organization. Review whether further usage could be billed after the credit is exhausted. The paired Pages mission route uses local inference. The public site has no member credential store. ## Français

MON FRONTIER transmet votre ambition intégrale au moteur de missions HARNESS sur votre appareil. Le journal conserve l’approche, les appels au modèle, les opérations autorisées, les refus, les fichiers et les vérifications. Vous pouvez le retrouver dans **Mes résultats** après avoir fermé le navigateur.

1. Dans **Intelligence → Utiliser l’intelligence sur mon ordinateur**, téléchargez et extrayez l’exécuteur local. Ouvrez le fichier `Launch-FRONTIER` correspondant à votre système. Python 3.11 ou une version ultérieure est nécessaire. L’exécuteur a été testé sous Linux. L’installation native sous macOS et Windows reste à qualifier.
2. Démarrez un moteur de modèles compatible sur votre appareil. Le guide local mène aux installateurs d’Ollama, de LM Studio, de llama.cpp et de vLLM. Pour un port personnalisé, utilisez `--config` et un fichier de configuration local approuvé, par exemple `local-model.example.json`. Vérifiez le téléchargement et la licence du modèle avant l’installation.
3. Activez votre ambition dans **Mon Frontier**. Ouvrez **Configurer mon intelligence**, jumelez le navigateur avec le code à usage unique affiché sur votre appareil, puis sélectionnez **Détecter les modèles locaux**. Choisissez un modèle et lancez sa vérification. Après un essai local réussi, MON FRONTIER reprend automatiquement l’ambition déjà saisie.
4. L’exécuteur conserve votre choix dans son espace privé. Après son redémarrage, utilisez **Reconnecter mon modèle** pour vérifier à nouveau le modèle choisi. Dans **Mes résultats**, ouvrez **Enregistrer ou rouvrir une mission** pour retrouver le journal et poursuivre le travail autorisé.

Si aucun modèle n’est prêt, vous pouvez passer par le guide de connexion ou préparer une mission à transmettre vous-même à ChatGPT ou à Codex. Cette transmission constitue une exécution assistée. Vous pouvez demander à l’exécuteur de privilégier les outils déterministes qualifiés. La préférence reste soumise aux mêmes permissions et n’active aucun fournisseur payant.

Le journal permet de suspendre, de reprendre, d’annuler ou d’exporter une mission. Pour restaurer une archive, utilisez `--mission-model MODÈLE --mission-import /chemin/vers/frontier-execution.json` avec la configuration privée. Examinez le journal importé avant de reprendre. Pour autoriser un dossier de preuves, l’opérateur utilise `--mission-evidence` et rattache le dossier à une ambition exacte, dans une langue déterminée. Le moteur vérifie la provenance, l’empreinte, les unités, le résultat exécuté et la référence. Un désaccord reste visible. [Rejeu du calcul de mélange](claim-binding/REPLAY-RECEIPT.json)

### ChatGPT et Codex

L’espace HARNESS local présente les options de connexion officielles et vérifie leur disponibilité. Consultez l’autorisation affichée par OpenAI avant de transmettre un travail. Le connecteur consigne l’exécution terminée pour le compte et la voie concernés. L’étude a vérifié la découverte native de Codex et exercé les protocoles avec un compte simulé. La connexion d’un compte réel et la construction avec Codex dans un environnement isolé restent à qualifier. [Guide ChatGPT et Codex](../../products/alpha-genesis-harness/docs/CHATGPT-PLAN.md)

### Accès API autorisé

Saisissez vos identifiants autorisés dans l’espace HARNESS local. Vérifiez le projet, le modèle, le solde et les limites de dépenses. Si votre abonnement donne droit à des crédits API, activez-les par la voie officielle et vérifiez leur inscription dans l’organisation API correspondante. Consultez les options de facturation après épuisement des crédits. L’exécution jumelée de MON FRONTIER utilise l’inférence locale. [Admissibilité et activation officielles](https://help.openai.com/en/articles/20001626-api-credits-benefit-for-eligible-chatgpt-subscriptions)
