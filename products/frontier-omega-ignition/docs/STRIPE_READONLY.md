# Optional direct Stripe settlement observation

The local `commercial` command can reconcile one delivered, full-price offer to funds available in the seller's authenticated Stripe payments balance. The observation records gross, fees, net, currency, provider request fingerprints and observation time. Subsequent refunds, disputes, bank payouts, profit and legal identity verification require separate evidence.

1. Before offering, the operator separately verifies merchant and customer identities and obtains the ID of the intended, still-uncharged PaymentIntent from the existing authorized checkout. Prepare a private JSON file containing exactly `merchant`, `customer` and `payment_intent`. Keep the raw IDs outside the mission journal. Generate the normal offered template with `python -m ignition --state DIR commercial ID --version V --stripe-offer PARTIES.json`. Complete the actual offer, evidence and authorization fields, then import through the usual `--record` command.
2. Run `commercial ID --version V --stripe-metadata` to obtain the opaque offer binding. The separately authorized checkout must put it on the resulting charge as metadata field `ignition_offer_sha256`. Metadata is merchant-editable. Independent checks bind the pre-enrolled PaymentIntent, customer, merchant, price, currency and charge creation time to the offer.
3. After recording actual acceptance and recipient acknowledgment, prepare a private request with those same three identifiers and the additional `charge` ID. An authorized operator with an existing restricted live key on an explicitly selected file descriptor may invoke `commercial ID --version V --stripe-reconcile PRIVATE.json --stripe-key-fd FD --control-sequence N`. Read `N` from current commercial status. No models, web endpoints or scheduled work invoke this command. Keep credentials out of command lines, JSON files, output and repository history.
4. The adapter issues two HTTPS GETs to the fixed Stripe origin. It retrieves the current authenticated merchant and then the exact charge with its balance transaction expanded. The key needs permission for those reads. Configure restricted read permissions for the merchant's integration. The client cannot inspect every grant associated with the key. A missing grant, pending balance entry or mismatched enrollment leaves the offer unpaid. A supplied statement or fixture cannot enter the live import path.

Supported direct charges use the same currency throughout, currently CAD, USD, EUR, GBP and JPY. The charge must be fully captured, undisputed and unrefunded. The authenticated available balance entry must point back to the same charge, record positive net and reconcile gross less fees. The local observer deduplicates charge and transaction fingerprints within its private workspace. Historical observations remain available across process restarts.
