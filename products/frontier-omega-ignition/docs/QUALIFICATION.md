# What IGNITION has demonstrated

The first two accepted public missions produce operational artifacts. The release auditor identifies byte and membership differences in a delivered package. The editorial migration infers a transformation from examples and applies it to held-out records. Each recipient ZIP contains its source, frozen contract, machine-readable receipt, independent comparator and CLI. The third mission, a physical measurement request, is deferred.

The engineering decision is **proceed with the bounded workbench and hold the Blue Sky flagship claim**. Ordinary tools produced the same required outputs on these workloads. Acceptance of an editorial or release tool supplies a technical capability. The unmet institutional question is whether the research and construction loop can unlock a valuable outcome unavailable to a competent complete alternative.

## Evidence by question

| Question | Inspectable answer |
| --- | --- |
| What supplied the research? | Public examples carry publisher-attributed source excerpts and actual retrieval times. Opt-in acquisition uses the shared HARNESS transport for current releases and earlier commit pointers. Every investigation separately labels capability access and historical uncertainty. |
| What produced the initial public artifacts? | Eight reviewed, request-bound exchanges with the included Codex session, with production, approval and model-usage boundaries disclosed. The assisted integration issued zero model API calls. The operator knew the public examples. |
| What runs automatically? | Under explicit mission authority, the private controller uses an installed Ollama or llama.cpp model for discovery, challenge and construction. It executes only validated data-language operations. The registered hosted trial independently measures the weight bytes and records actual call outcomes, including rejected or deferred runs. |
| What did recipients reproduce? | Both originals passed nine checks on extraction and processed their example input in a separate Python process. The replay script verifies archive identity, reevaluates with the checkout’s checker, then builds and exercises a fresh bundle. Replay runs zero new model calls. |
| What did capable ordinary alternatives achieve? | GNU Coreutils plus inventory matched five of five declared release cases. jq matched four of four declared migration cases. The example-only mapping learner abstained on ambiguity. The ordinary alternative therefore resolves the public correctness task. |
| What makes a loss visible? | Research can promote a challenger, select an incumbent, defer or stop. The verifier checks candidate outputs, prescribed semantics and refused inputs. Technical failure, stale state and incomplete evidence block current delivery. Histories and recorded losses remain available. |
| What is reused on later missions? | A retained executable program may be supplied as construction input under explicit rights. The successor receives fresh authority and acceptance. Same-mission history surfaces previous obstructions worth retesting after new evidence. |
| What economic value was established? | Technical delivery and reproducibility. No customer, paid acceptance, complete-cost improvement, matched human-time saving or historical crossing was observed. An optional commercial worksheet separates assumptions, unknowns, telemetry and prospective costs from actual transactions. |
| What is outside this qualification? | General-purpose code generation, cryptographic proof of model inference, tenant-isolated hosted service, general project migration, physical actuation, payment, customer outreach, operational customer acceptance, and measured improvements across successor missions. |
| What is published? | A draft source change stacked on the existing research edition, public examples and reproducible packages. Review, integration, release and deployment require their own evidence. |
