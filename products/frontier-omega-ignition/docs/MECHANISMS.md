# How a research decision changes the construction

The [repository research foundations](../../../docs/harness/RESEARCH_FOUNDATIONS.md), [published mechanisms](../../../campaign/blue-sky-064/MECHANISMS.md) and [Out papers](../../../docs/harness/OUT_PAPERS.md) motivate the following concrete decisions. They describe different strengths of evidence. Model suggestions remain hypotheses. Conditional results from the earlier mathematical instruments retain their original scopes.

| Mechanism | Where it can change this product’s decision | Inspectable boundary |
| --- | --- | --- |
| Structural transfer | Discovery asks for a structure that can serve the mission elsewhere. An example-based migration can transfer a formerly unseen input field into an editorial classification by splitting its identifier. | A proposed correspondence alone earns no acceptance. The resulting program must transform the frozen held-out records correctly. General cross-domain transfer is unqualified. |
| Adversarial discovery | The challenge call can inspect the answer, widen the set or challenge the instrument. It can add a candidate or favor an ordinary alternative. | Source IDs, objection scope and quoted witnesses are checked. A model interpretation can remain unresolved. The public audit’s sixth candidate replaced the initial favorite. |
| Strategic invention | The team can preserve the requested outcome while proposing a different delivery route, such as checking an independently pinned manifest and complete file inventory with zero signing credentials. | The run retains the alternatives, their costs and the decisive test. A viable change of means does not establish that the method was invented here. |
| Problem transformation | The mission separates the purpose and binding requirements from the proposed implementation. Construction compiles the selected means or requests a reviewable specification. | A changed purpose or unsupported requirement cannot inherit a prior acceptance. Physical qualification stayed deferred. |
| Epistemic invention | Each candidate proposes an observation that could resolve its obstruction. The complete-release experiment changes the received files and then changes the received receipt itself. | Independent, externally fixed expectations identify which files changed. The ordinary tool faces the identical three deliveries. |
| Self-correcting evidence | The application checks source identities and retractions, refuses incorrect oracles in fully specified tasks, tests negative controls and re-evaluates before export. | Identifiers only bind data. Acceptance covers the actual checker and frozen workload. |
| Generative capability inheritance | Under an explicit originating grant, a successor can use the retained executable program as a candidate on a different mission. | The successor supplies fresh permissions, tests and resources. Causal improvement in successor economics requires a fresh matched comparison. |
| Recursive economic and strategic selection | Challenge admits an incumbent, non-entry or delay. An optional commercial assessment tests a proposed arrangement against complete cost categories and named outside options. | Unknown prices, unpaid demand and absent financing stay unknown. Neither a technical tie nor the commercial worksheet establishes customer payment. |

The concrete claim of this implementation is the ability to investigate and construct within the stated domains. Reliable open-ended invention and recurring economic advantage would require materially different evidence.
