# Operating IGNITION safely

The public GitHub qualification uses public, synthetic missions. Operate customer work separately in a private, owner-controlled environment. Before submission, agree on what the operator may read, what the model may receive, what outputs the customer can keep, and the retention period. Minimise the material submitted. Keep state on an encrypted, access-controlled volume. A collaborator with access to that volume can read the mission. Local browser access is a trust boundary, not tenant isolation.

## Mission and evidence boundaries

Treat source documents, retrieved text, model completions and artifact input as untrusted data. A sentence in a source cannot consent to another fetch, add a tool, expand the execution budget, choose a recipient or grant publication. A file digest identifies bytes; corroborate the source identity and independently test any claim on which acceptance depends. Inspect the actual conditions in a receipt before reusing it for another mission.

Model configurations require an explicit, authorized inference route. Never enter API keys in mission text, artifacts, issues, or Actions settings for this workflow. Use a clean profile for demos. Keep database files, journals, backups, customer text and model transcripts outside Git. The public model job uploads one named synthetic-trial receipt; review its fields and the exact workflow source before authorizing customer-specific changes to the publication boundary.

## Retention, deletion and incidents

For a retention agreement record the owner, expiry, storage location, backups and any copies delivered to the recipient. At expiry, the owner should stop the local service and remove the complete authorized mission store and any exports covered by the agreement, including database sidecar files and backups at their agreed expiry. Where a store contains several customers, migrate or isolate it before erasing anything. Erasing a file on a shared disk alone does not guarantee physical media sanitization. Confirm the scope before destruction. Quarantine suspicious evidence away from the working store. Preserve only the evidence necessary to investigate under the applicable agreement.

## GitHub qualification boundary

The workflow checks out the exact candidate commit into a standard ephemeral GitHub-hosted job. Checkout credentials are not persisted, external actions are pinned to the immutable identities also used by HARNESS, and the token receives read-only repository contents permission. Qualification uses ordinary pull-request events, no environment secrets and no deployment step. Separate jobs report application behavior, primary-source acquisition and local model execution. The source probe publishes one synthetic-mission evidence receipt. A model trial that cannot execute or fails acceptance must be inspected as such even if the application tests pass.

Anyone who can change the workflow or qualification scripts can change what those scripts claim, request or upload. Review changes to these files alongside review of the executable and the oracle. A public PR job must never receive confidential customer inputs, host credentials or private state. Authentication, multi-tenant isolation, remote TLS termination and abuse controls require their own qualification before offering a hosted customer service.

## Continuation qualification

The private service still binds to loopback. The operator explicitly chooses the benchmark specialist or supplies a typed construction contract. Public presets populate fields without turning on model calls, retrieval, or reuse permission. A repaired construction is a new candidate under the original evaluator. Frozen reference values can be bound directly from the trusted operator contract. The builder receives a count and category of failures plus differences from its public development definition; the held-out inputs and labels stay with the independent checker.

The public Pairing Lab exhibition reads only fixed, licensed repository files. The service returns it at `/showcase` with an opaque sandbox origin and a separate content security policy. Its scripts and styles are content-hashed. The standalone exhibition has no private API connection. The public recipient ZIP explicitly enumerates its files. Private benchmark export adds the verified numeric decision; a mission's free-form intake, conversation and authorization data are excluded.

Fresh pilots require a separately retained commitment before observation. The auditor reconstructs the plan on its exact selection data and executable, checks the requested stacks and thresholds, and distinguishes an incomplete set of observations from a failed pilot. The source and labels of external grades remain the operator's responsibility. CSV grade import grants no authority to execute arbitrary code. The original research agents' patch submissions are outside the downloadable kit.

Relevant regressions are `tests/test_adaptive.py`, `tests/test_pairing_mission.py`, `flagship/test_pilot.py` and the private/public Chromium checks. The review covers the repository implementation and these exercised boundaries. A public multi-tenant service, a production grader for untrusted patches, and a paid inference connector require separate designs and qualification.

The public Reading Room exhibition at `/exhibition` serves a prebuilt HTML file with the same opaque sandbox policy. Its only embedded recipient contains the named public research sources, instrument and registered evaluation. The browser reads local bytes and requires no private workspace or model connection.

## Private astronomical follow-up

Open `/follow-up` or `/follow-up?lang=fr` on the loopback workbench. The planner can vary the number of available windows and the required visits per target in its installed historical catalog. The worker sends a fixed local Python recipient the public catalog, modeled site, modeled windows and selected planning parameters. It supplies no private beneficiary text, model credentials, prompts or telescope interface to that process.

A revision binds the brief, the public inputs and the exact planner and independent evaluator. Revising the cadence or resource allowance requires fresh acceptance. History remains inspectable after amendment and a superseded export is refused. The downloaded recipient contains the public input, the selected planning scope, the worklist, the independent comparison and their fixed code. Extract it and run `python3 -IB review_followup.py`. The recipient reproduces the geometric plan. Obtaining telescope time and executing observations are separate operations.
