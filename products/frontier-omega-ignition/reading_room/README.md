# Reading Room

Give a reader a linear edition of an authorized manuscript in which they can open the original PDF at the page containing a passage. The author’s manuscript supplies the words and order. Each passage independently gets a page link, a list of possible pages, or an unresolved label. Both original inputs travel with the edition.

## Build an edition

Use Python 3.11 or newer and Poppler’s `pdftotext` on the command path. From this directory, point the command at local files you are authorized to process.

```bash
python3 edition.py --pdf publication.pdf --source author-reader.html --output /tmp/first-edition
```

Open `/tmp/first-edition/index.html` in a browser. The original PDF, an inert copy of the source manuscript, and a machine-readable receipt sit alongside it. Share the complete directory if publication rights permit. The in-page PDF links use physical page numbers starting at one. A PDF viewer that ignores page fragments can still open the original file so the reader can navigate to the indicated page.

For a selected reading path, supply a UTF-8 JSON manuscript instead. Keep exact wording, punctuation, units and sign characters in the block text.

```json
{
  "title": "Research notes",
  "language": "en",
  "blocks": [
    {"kind": "heading", "level": 1, "text": "Results"},
    {"kind": "paragraph", "text": "Copy an exact passage from the authorized manuscript here."}
  ]
}
```

Headings support levels one through six. The reader preserves the supplied sequence and scales heading levels to sit below the edition title. The HTML input route imports visible-by-markup heading and paragraph text inside `main`, then `article` if there is no `main`, then body content. Navigation, footers, controls, scripts and hidden/inert elements are excluded. Passages with embedded math, images or other media keep their place and textual fragments, receive a visible source-review label, and stay unlinked. The receipt records the element types and review reason. Plain list items, table cells, image-only content, visual mathematical notation and CSS-dependent visibility need a separately authored semantic edition where they matter. Entity references and inline emphasis contribute text. Manuscript links and active markup do not execute in the output.

## Interpret the receipt

| Status | Reader behavior |
| --- | --- |
| `matched` | One physical page’s extracted text contains the passage. Open that page to inspect the original. Repeated occurrences on the same page still identify one page. |
| `ambiguous` | Two or more pages contain it. The reader displays their numbers and leaves the passage unlinked. |
| `missing` | No page contains the entire passage under the matching rules, or an embedded-content review reason disqualifies automatic linking. The passage remains visible for review. |

The instrument uses Poppler’s default reading-order extraction, splits pages at Poppler form-feed separators, composes Unicode NFC, expands common Latin typographic ligatures and collapses whitespace. Matching preserves case, accents, punctuation and numerical signs. Token-boundary and decimal/sign checks guard against several incidental substring matches. There is no inference or fuzzy recovery. Scans without text, line-end hyphenation, a passage split across pages, multi-column extraction and differences between editions can all leave passages unresolved. A unique text-layer occurrence gives a place to inspect. A human reader may still find an inaccurate text layer, a misleading quotation in context, or important material absent from the manuscript. Coverage measures supplied eligible passages only. The edition does not certify a complete transcription, PDF accessibility or scientific validity.

The receipt records all candidates, block text, selection scope, PDF page count, extractor version and SHA-256 digests of both input files and the running instrument. Rebuild from the received files and compare the generated bytes using the same Python and Poppler versions. Use the `source_format` in `receipt.json`.

```bash
python3 edition.py --pdf /tmp/first-edition/source.pdf \
  --source /tmp/first-edition/manuscript.original.txt --source-format html \
  --output /tmp/rebuilt-edition
cmp /tmp/first-edition/receipt.json /tmp/rebuilt-edition/receipt.json
cmp /tmp/first-edition/index.html /tmp/rebuilt-edition/index.html
python3 -m unittest discover -s . -p test_edition.py -v
```

A build requires a new or empty output directory. It stages all files before delivery and refuses to overwrite a previous edition. A completed build may include unresolved passages. The process reads local inputs, runs the installed Poppler executable directly and makes no network or model requests. The output contains the entire input PDF and manuscript. Use it locally for authorized source material and review its contents before distribution.
