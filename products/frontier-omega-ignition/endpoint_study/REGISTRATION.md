# EP01 · Which published configurations merit a real load test?

Decision frozen 17 November 2026. MONTREAL.AI can use the published MLPerf Endpoints evidence to choose a measured load point for a subsequent infrastructure pilot. This study tests whether the decision can be made reproducibly with every named constraint and the original full reports. It exercises an internal research decision only. Access to the tested clusters, production traffic, reader or buyer participation and purchase are outside current authority.

## Fixed population and workload

Use all columns in three official MLCommons Endpoints phase 2 reports. The verified Google GPT-OSS 120B perf report (d6b88dff-6bbb-4107-8d2e-1090decd4d53, published 4 November) is primary. The separately reported Google DeepSeek agentic-dataset report (3fdca196-7298-4b65-832d-d455abd792eb) is the prespecified different-model transfer. Include pending NVIDIA submission 053005da-b0ad-495d-9721-e39e9b144bd8 to test exclusion. The source URL is https://results.mlcommons.org/endpoints/report?source=phase2&submission= followed by the submission ID. The discovery team inspected the sources; this is a prospectively frozen decision comparison on public data, not a blinded discovery. Record full document hashes, source dates, numerical formatting, submitted model, dataset, verification status and deployment scope.

The frozen [contracts](contracts.json) specify two genuinely different workloads, an explicit tail-rate comparison, an unreachable threshold, a mode unverified in the GPT report, a different traffic population and three unsupported obligations. Thresholds are illustrative lab pilot requirements, not inferred market SLAs. GPT's “submission” config type supports reported positive concurrency but does not assert that its run was labeled online. Explicit online requires the literal reported mode. Only consider completed, verified, standardized Client on Premises rows with positive measured concurrency, real numerical latencies, zero failed queries and matching model and dataset. Use the qualified configuration region rules from the benchmark (exclude offline data). If accuracy, price or access is required, demand matching measured evidence. Reported token rate per user and reciprocal P90 inter-token latency are different measures. For the latter compare rate multiplied by reported P90 time per output token, in milliseconds, to 1000 using exact decimal semantics. No claim about the unmeasured joint end-to-end P90, agentic turn completion or service uptime is permitted.

## Arms and independent adjudication

1. Execute the private/public candidate consumer on the exact contracts, and retain selected (source ID, 1-based run) pairs, corresponding physical source values and each refusal.
2. Independently extract all operating points from the retained full report tables; SQL selects every tie at maximal eligible concurrency using exact decimal comparisons. Give a conventional analyst the same constraints, all reports and the public method, without candidate projection code or scorer key. Compare status and every returned source/run identity, concurrency, TTFT and source rate rather than headline counts. If the direct route ties, use it as the economic incumbent. Include an ordinary full-report/SQL recipient and its output in the export.
3. As a clearly weaker diagnostic, record the maximal *system throughput* reported for the correct verified workload ignoring per-user responsiveness. Count rate/latency misses; never silently replace the complete comparator with this rule. A no-entry option is available if no run meets the requested requirements.

For genuine non-admission controls, require explicit withholding with no selected rows for wrong workload, required but unmeasured point accuracy, missing price, missing physical access, unverified online GPT mode and the stringently impossible latency. Tests must distinguish reported vs reciprocal P90 semantics even if actual selected points coincide. Independent graded perturbations must refuse a swapped source/run ID, changed TTFT, and missing or spurious tied row. Count and disclose every failure. Freeze the approach here before running the candidate or SQL score. A reproducible candidate may still tie or lose. Do not use scorer outcomes to tune the frozen contract.

Success means agreement with independent complete evidence on all registered contracts, refusal of the negative controls, no false positive support and materialized pilot selection on at least one primary and one distinct-model contract.
