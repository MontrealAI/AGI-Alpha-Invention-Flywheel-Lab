Only external evidence can establish buyer acceptance.

Stop is terminal for that mission. Add `--sequence S` to require the control state you inspected. The private browser exposes the same controls and commercial history. `serve --recover` also resumes active queued or interrupted revisions under their existing authority. An interrupted uncommitted field measurement is identified as such.

Inspect a commercial record with `commercial ID --version N`. Supply `--template STAGE` to see the evidence required for a transition. The journal stores their hashes and source descriptors. An offer or delivery must match the exact ZIP. Record only authorized actions actually taken and preserve an independent basis for the authenticity of outside records.

## Operator guide

For a trusted, installed loopback inference server, set the exact provider and model ID as described in [Model routes](docs/MODEL-ROUTES.md), then run `serve`. For an explicitly authorized operator-assisted exchange:

```sh
python3 -B -m ignition --assisted "Provider actually used" "Model actually used" serve
```

The local browser shows a pending request and a request digest at each assisted step. Review the request before sending it through an authorized channel. Supply only the model response JSON. The server checks that it belongs to the pending stage, mission, provider and revision. The application never needs account credentials for an assisted exchange.

Start from company purpose, beneficiary, and acceptance requirements. The brief accepts rights-authorized JSON specifications and source excerpts. Give separate consent for public feed acquisition and the chosen model route. Public retrieval sends fixed publisher requests without company text. Here are [worked mission files](examples/) and the [registered live acquisition procedure](docs/SOURCE-QUALIFICATION.md). Unsupported file uploads, open-ended code deployment, payments and contact with buyers have no execution interface.

An existing specification supplies exact acceptance inputs before model construction. For a freeform ambition, the system can propose a bounded specification. Review it and supply fresh confirmation inputs before approving it. The builder receives public development examples and schema definitions. The verifier sees the frozen confirmation workload. A provider may share external context with an operator, so independence of the operator remains separately disclosed.

A freshly generated release receiver also supports `python3 -I run.py audit-directory /path/to/release`. It streams real files and reports the complete inventory. The [full-edition experiment](evidence/release-handoff.json) exercises a 15-file delivery, including a deliberately rewritten manifest. A freshly exported migration supports `python3 -I run.py migrate-jsonl < input.jsonl > output.jsonl`; a bad row stops execution after the preceding valid prefix. The original recorded ZIPs retain their original commands. Generate current-source recipients with `python3 -B examples/requalify_recorded.py --output NEW_DIRECTORY`.

Use `--state PATH` before the subcommand to choose a private directory. The default is `~/.frontier-ignition`. Use the same state path and provider options across CLI invocations.

| Operation | CLI |
| --- | --- |
| Start or repeat the same intent | `python3 -m ignition start examples/migration.json --request-id my-migration-001` |
| Inspect the current mission | `python3 -m ignition show RUN_ID` |
| Resume after an interruption | `python3 -m ignition resume RUN_ID --version 1` |
| Submit a reviewed assisted response | `python3 -m ignition respond RUN_ID response.json --version 1 --sha256 REQUEST_DIGEST` |
| Confirm a proposed scope | `python3 -m ignition approve RUN_ID fresh-cases.json --version 1 --sha256 PROPOSAL_DIGEST` |
| Amend requirements or authority | `python3 -m ignition amend RUN_ID revised-mission.json --version 1 --request-id specific-amendment-001` |
| Inspect earlier work and open leads | `python3 -m ignition history RUN_ID` and `python3 -m ignition inventory` |
| Run or export an accepted program | `python3 -m ignition try RUN_ID input.json --version 1` and `python3 -m ignition export RUN_ID result.zip --version 1` |
| Use a retained program as a candidate means in a new investigation | `python3 -m ignition successor RUN_ID new-mission.json --version 1 --request-id unique-successor-001 --rights "Specific rights basis"` |

Reuse requires the original mission’s `allow_program_reuse` grant. The successor supplies its own authority and new acceptance conditions. Locally recorded program reuse does not prove an economic or discovery improvement. Each artifact link exposed by the live application requires an accepted current revision. The operator can inspect historical evidence separately.

The [mechanism map](docs/MECHANISMS.md) traces the Eight Fundamental Mechanisms into research decisions, tests and their limits. To investigate a public repository beyond the curated monitors, specify its canonical GitHub repository URL in `resources.public_repositories` and explicitly grant public-source retrieval.

## Implementation and deployment

| Component | Responsibility and reuse |
| --- | --- |
| [Mission controller](ignition/controller.py) and [state store](ignition/store.py) | SQLite revisions, per-run operation identities, worker synchronization, checkpoints, authority and invalidation. Mission records have their own schema because the older HARNESS arithmetic workflow has a different acceptance object. |
| [Frontier research](ignition/research.py) | Forward release-feed and backward mission search. Attributes publisher, event, retrieval, access and prior evidence. Generates options, challenges the set and tests source eligibility. A stronger sixth opportunity or a conventional alternative can win. Same-mission amendments surface retest leads when the underlying evidence changes. |
| [HARNESS provider bridge](../alpha-genesis-harness/bridge/adapters.py) and [IGNITION model interface](ignition/provider.py) | Reuses the existing local transport and DNS-pinned public source reader. Only model JSON crosses into construction. Recorded and assisted exchanges have distinct provenance. |
| [Constructor](ignition/construction.py) | Interprets a validated, bounded data language with no generated Python, dependencies, shell, external actions or network. Supported migration instructions include checked conversion, projection, split and join. |
| [Evaluator](ignition/evaluation.py) and [delivery](ignition/delivery.py) | Separate algorithms, negative controls, predeclared cases, conventional comparators, source-bound receipts and portable packages. Re-evaluates before export. |
| [Matched comparison](ignition/compare.py) | Executes two attributed, dated programs on identical acceptance data. Invoke `python3 -m ignition.compare protocol.json before.json after.json`. Each arm declares version, source, availability date, budget conditions and artifact. Historical availability and complete construction costs require additional evidence. |
| [Local service](ignition/server.py) and [experience](web/) | Loopback-only HTTP, exact origin and host checks, action-specific JSON API, private amendments, read-only replay, keyboard and mobile interaction. |

The [commercial assessment](docs/COMMERCIAL-ASSESSMENT.md) records observed model use, buyer outside options, rights, missing costs and obligations. Operators may supply labeled ranges in `resources.commercial_case` for a separate fixed-cost, variable-cost and break-even scenario. Prices, financing and operator-entered assumptions carry no financial authority. Model requests omit the commercial worksheet. The canonical enterprise accounting system remains the sole operating ledger.

The existing public research pages still host the earlier authored editions. This app has its own local deployment boundary because public GitHub Pages cannot execute a private mission worker. The approved deployment target for this draft is an individual operator’s loopback workbench. Customer-facing hosting would require a separately authorized deployment design with authentication, tenant isolation, transport encryption, rate limits and retention controls. This PR publishes source and public fixtures only.

Use a single-operator machine and a private, access-controlled state directory on an encrypted volume. Store reviewed public fixtures apart from customer work. Mission data remains in the selected private directory until the operator’s agreed retention date. Keep customer states in separate directories so an authorized operator can retire a complete customer workspace, including backups under its retention agreement. Underlying disks, snapshots and backups govern erasure guarantees. See [security and trust boundaries](docs/SECURITY.md).

An external IGNITION engagement is a separately scoped delivery with explicit rights, objective, acceptance inputs, permitted actions and handoff. Customer data or a customer’s reusable means require explicit rights before internal reuse. The retained technical platform supports MONTREAL.AI’s internal program. IGNITION opens no continuing service obligation or financial account.

## Verification and troubleshooting

```sh
python3 -B -m unittest discover -s tests -v
python3 -B examples/compare_conventional.py
python3 -B examples/requalify_recorded.py
```

GNU Coreutils and jq are needed for the standalone conventional comparisons. Archive requalification runs the delivered programs outside the source tree. Chromium suites, live source acquisition and the pinned CPU model trial use [the exact-head qualification workflow](../../.github/workflows/frontier-omega-ignition.yml). Public original runs are available under [evidence](evidence/). The checks establish their named observations. Strategic differentiation, payment, complete-cost profitability and a five-week frontier crossing remain separate questions.

| What you see | What to do |
| --- | --- |
| Model unavailable | Configure a trusted local route or explicitly start an assisted session. Reopen or amend the mission with the desired route and permission. |
| Awaiting model / contract | Use the matching request SHA. Supply a reviewed response or fresh independent confirmation cases. |
| Source feed unavailable | Inspect the recorded feed and failure. Recheck permitted egress or supply an attributed, rights-authorized source snapshot. A dated announcement can motivate a test. |
| Deferred or conventional method wins | Inspect the selected outside option, scope objection and next decisive test. Keep the original result. |
| Rejected input | Correct the input to match its declared schema. The interpreter refuses unsupported operations and out-of-domain values. |
| Stale or changed revision | Open the latest revision, inspect history, and amend under the current provider/source. Historical receipts identify their original scope. |
| Interrupted stage | Resume using the same run, revision and provider. Completed calls are durably reused. An interrupted local generation can consume additional computation on a deliberate retry. |
