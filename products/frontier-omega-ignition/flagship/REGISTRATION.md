# Pairing Lab qualification registration v1

Registered 2026-11-17 before computing the study split or looking at any per-policy outcomes. The public paper's headline cell-level results were already known. This is a retrospective task-disjoint analysis of published observations, not a blind new model trial. Preserve this registration on any repeat.

**Beneficiary.** MONTREAL.AI's engineering operator needs to decide whether a private coding team should pilot a self-hosted configuration for issue resolution, under a resource allowance and independently executable issue acceptance checks. Authority covers an offline decision and experiment design only. No deployment, purchases or work on arbitrary repositories.

**Design.** Parse the compact five-column projection of the 1,800 measurements in Zhao, Poskitt and Lo (2026). Pin upstream blob 59cb87ce1be885936e21037c9f0699bd9dff5cb0. Require complete paired observations per issue, unique task/configuration rows, integer token volumes and exactly binary resolution labels. Partition unique issue IDs ranked by sha256 of UTF-8 'pairing-lab-v1/' plus ID (ID breaks ties). First floor(3N/5) calibration, remainder audit. Filter by repository after this split. Select policies from calibration exclusively. Fit no model. The complete configurations compete together unless an operator prospectively restricts the model.

**Decision.** Enumerate all permitted singles and, in width-two mode, all unordered pairs of distinct configurations. A pair charges both recorded attempts on every task and earns at most one success, when either patch met the archived independent grader. This is offline achievable coverage conditional on an equivalent independent task oracle at use time. Its verifier costs and the cost of running a second model are operational obligations. With an average charged-token budget per issue, admit a policy only when its total reported tokens do not exceed the budget times task count. Rank by resolved tasks descending, then total tokens ascending, then sorted configuration names lexicographically. Permit no candidate when the constraint is infeasible. Expose the audit hindsight optimum separately. Qualification requires the locked policy to meet the registered mean-token ceiling and resolve at least the configured fraction of audit issues (default 45%, illustrative for this mission). Budget limits are paper-metered tokens and exclude cash, hardware occupancy and verification effort.

**Frozen exercises.**
1. Main mission: all 18 configurations, 2,000,000 charged tokens/issue, minimum 45% audit resolutions. Compare width one and width two. Also run at 500,000 and 5,000,000 tokens/issue for sensitivity. Report all, including failure.
2. Incumbents: exhaustive independent SQL over exactly the same feasible singles/pairs; global incumbent selected by calibration resolutions without cost gating; held-out hindsight optimum as a nondeployable information bound. The paper already provides descriptive tables. A trained human with SQL can implement our finite search. No incremental discovery or historical exclusivity follows from parity.
3. Adversarial check: a deliberately defective comparator discards charges on failed attempts. A synthetic fixture must reverse the budget decision, expose the discrepancy, and pass with full charging. Test missing pairs, duplicates, invalid inputs, no feasible policy, audit-only outcome perturbations, SHA-bound input identities and deterministic export.
4. Successor: same tool, new authorized ambition to qualify a privacy team's existing Devstral-only stack for Django issues, 2,000,000 tokens/issue, width two, 45% audit floor. Ordinary unchanged software reuse and independent SQL receive identical rights. Count the extra evaluation and report actual coverage. No superiority to fresh construction without an independently reconstructed challenger.
5. Portable receiver: run using Python standard library only from a newly extracted bundle with no network. Read manual input changes as new analyses requiring requalification. Compare every search configuration on the public cohort to the independent SQL reference. No inference replay, client data, claims of production reliability, paid demand or economic surplus.

**Revisions.** Changed requirements, data or program identity invalidate the original result. Emit a receipt binding exact input, executable and policy parameters, with witnesses on each audit issue. No evidence certificate authorizes real-world action.
