# Frequency of the sparse fallback across a production schedule

The previous six positions were chosen for coverage, including both endpoints. The current question is how often accelerated sparse inputs occur among the remaining 2,116 scheduled forward inputs in the published PHerc0139 w054 example. Freeze the reference recipient, baseline code, previous six exclusions, selection seed, workload, outside option and analysis before acquiring the new full-resolution voxels.

Select 24 distinct remaining indices by ascending SHA-256 rank, using the public protocol in sample_schedule.py. Use all selected cases, including all-fill windows. Verify every allocation against both shipped C++ alternatives, with rotating trial order and seven timed repetitions after warmup. Report zero-MAD frequency, summed incumbent and candidate medians, ratio of those sums, and median per-window ratio. No timing gate or favorable-outcome selection. Any byte disagreement fails the comparison. A single-window median or an aggregate in this sample may favor either implementation. The selected indices share one source volume, so this design cannot estimate cross-scroll performance, GPU wait, full-reader latency or buyer value.

Allow at most 175,000,000 bytes of successful application payload within the acquisition budget. Keep failed attempts. Distribute source references, sample selection, hashes and timings only. Run from this directory using the exact published offline recipient and a new local directory. The open provider scan is used for attributed research under CC BY-NC 4.0. Acquisition and compilation require network access to the existing public source and a GNU C++20 toolchain respectively.
