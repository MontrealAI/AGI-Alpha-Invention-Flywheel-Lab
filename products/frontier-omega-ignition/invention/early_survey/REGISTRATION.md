# Early-candidate archive experiment

The two registered SLSN-candidate cohorts supplied 40 eligible comparisons and no issue under the frozen rapid-change rule. This fresh comparison asks whether another actual archive desk can use an automated early-supernova candidate stream and its prior observations to issue a reviewable change notice, then check what the next survey detection showed. Fink's machine-generated tag is a selection aid, never confirmation of type Ia. The earlier two-cohort primary stays closed.

Before requesting any bytes for this cohort, freeze the Fink `/api/v1/latests` query for `Early SN Ia candidate`, `n=300`, 2026-10-18 through 2026-10-25 UTC. Do not request a rising/fading trend. Filter to the half-open selection interval by observation JD. Choose at most 36 distinct targets from the returned rows in order of most recent qualifying observation, then object ID ascending. This tests a finite desk capacity; the query is bounded and can return fewer targets. Query each admitted object for detected observations (no forced photometry), retaining candids, dates, band, subtraction sign, PSF magnitude/error, field, readout channel, public program ID and broker magnitude-rate fields where supplied. Check IDs and row projections. Report retrieval failures and every unadjudicated case. Compact projections and source byte identities suffice; record the exact requests and response shape. No new observing time, participants or service purchase.

**Acceptance.** From 25 October inclusive to 1 November exclusive, UTC, use the same registered nightly issue / 3-day first-witness rule, sign interpretation, numerical thresholds, event-time availability and censoring as [the original change contract](../evolution/REGISTRATION.md). Restrict the fresh detected population to ZTF public survey program ID 1. Require consistent nonmissing (`field`, `rcid`) and passband for every compared detection; compare within a common detector stream and report this stronger reference proxy. It does not establish a shared reference image/version or uncontaminated source. Preserve a notice for each target/band's first qualifying stream, use the latest current observation in that target/band/day then look only in its own stream for its baseline or witness. Do not reject a numerical candidate just because the broker reports a different rate. Its time baseline, treatment of upper limits, and uncertainty method may differ.

**Predeclared arms.** The cold route admits baseline observations from 25 October. The warm route also admits public source observations in the seven days before the cohort start *only for its baseline*. Both have exactly the same rights, issue times, trigger and holdback rules. A notice may only use measurements already visible at the UTC decision cutoff. Count alerts, unique targets, decidable/reproduced/reversed/not-reproduced, expired coverage and right censoring, and extra or changed witnesses after retaining prior history. A cold/warm difference may change either arm's first trigger. Show the actual paired status. With absent or zero results, preserve that obstruction; this registration makes no claim about the yield of other populations. Independently reconstruct from the source files using SQL and compare all detection IDs, directions, dispositions and signed quantities. Record a source-matched, labeled Fink `d:mag_rate` comparison at each issued trigger when available. Source-bounded output equality can establish software correctness. Prospective production latency, physical calibration, operator acceptance, incremental productivity and economics require separate measurements.
