# Instrument workshop · Atelier des instruments

## English

1. Extract the entire edition. Open the launcher for your platform or run `python3 launch.py`. The printed loopback address opens the same browser workspace with its private connector.
2. In **Model connection settings**, connect a model you run locally. Return to **Start here → The instrument workshop**. Select the model and confirm the data transfer for this mission.
3. Enter an ambition. Choose **Instrument Foundry** for the three-sensor experiment, **Source-grounded check** for a WCAG contrast preflight or **Shared design** for the hypothetical cost and participation screen. For your own task, describe the input and output fields under **Mission details** and supply independent JSON examples. For instance, a parts-dispatch instrument can receive `arrived` and `reserved` counts and return `ready` and `remaining`. Prepare examples for shortages, equality and surplus before starting.
4. Choose **Build and test**. **Mission** shows the decision and the question under test. **Workbench** shows runnable files and their relationships. **Evidence** shows the model requests, tool events, versions, tests, failures, and missing evidence. A pause or cancellation may leave an upstream request settling. Reopen the saved mission before explicitly resuming it.
5. Download the instrument and proof when work settles. Extract the result and run `python3 RUN_WORKSHOP.py check`. Run a new normalized input with `python3 RUN_WORKSHOP.py run INPUT.json`. Use `--profile optics`, `--profile pressure` or `--profile cold` for an original sensor format. Sample original records are in `PROOF.json`. **Prepare a fresh logger mission** offers a separate contract with fresh cases and a traceable predecessor.

The public GitHub Pages workspace supports offline drafting and the existing manual instruments. Connected construction runs in the downloaded application with the same browser assets. The loopback origin, session token and model configuration are specific to the local application. A configured API is a separate mode and requires its own access and operator consent. An ordinary ChatGPT subscription has separate billing from the API. See [OpenAI billing](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform).

### What the evidence means

- **Evidence still missing** means a check, observation or dependency needs work. An **evidence job** is a bounded construction and checking attempt.
- **Proof bundle** means the exported instrument, observations, tests, source identities, limits and replay files. The **decision** records admission, repair, rejection or changed dependencies. The capability registry retains admitted runs with their contracts. A successor checks its own cases.
- The last subset of each multi-case protocol is reserved for final qualification. The model receives the contract, previous instrument and aggregate development feedback. Built-in protocols may also give it a small synthetic counterexample from development. Final observations and labels stay in the evaluator. For an operator-authored mission, the evidence supports the operator's supplied cases and the model receives aggregate feedback.
- The founding experiment uses software adapters for one CSV optical micrometer, one JSON pressure station and one key-value cold-chain logger. Each has distinct acceptance and guard thresholds. A midpoint challenge follows the end-and-middle check standard approach in the [NIST handbook](https://www.itl.nist.gov/div898/handbook/mpc/section3/mpc37.htm). Real deployment needs traceable standards, repeat measurements, uncertainty assessment and a validated operating regime.
- The contrast preflight uses supplied measurements and classifications for [WCAG 2.2 criterion 1.4.3](https://www.w3.org/TR/2024/REC-WCAG22-20241212/#contrast-minimum). Branding alone supplies no exception. The shared design screen uses hypothetical costs, rights, budgets, outside options and cash timing. Fees and future promises are hypothetical. Complete economic advantage remains a separate measurement.

### Operator interface

The mission connector is loopback-only. Start separate profiles with distinct `--workspace /absolute/path` and `--port` values. Every `/api/workshop/` action requires the existing session header. `register` accepts an idempotency identity, model route, ambition, scope and case data. `get` returns a versioned projection. `start`, `pause`, `cancel`, `resume`, `revoke` and `bundle` bind the selected run and observed revision. A changed source hash or revocation reopens the admission decision.

The extension contract is a JSON instrument with declared `inputs`, optional named `bindings` and `outputs`. The model proposes formula strings. The bridge wraps each string in a declarative `formula` node and applies the sole approved construction tool. A formula can use arithmetic, comparisons, booleans, `choose(test, yes, no)`, numeric aggregation and references to input names or local bindings. The trusted runner interprets these nodes with operation and depth bounds. Attribute access, subscripts, dynamic calls, imports, filesystem access and network access are refused.

The public branch and candidate source have an independent release matrix in [WORKSHOP-QUALIFICATION.md](../evidence/WORKSHOP-QUALIFICATION.md). Release receipts should name the exact package checksum and browser source.

For a source-matched local reproduction, provide the pinned llama.cpp binary and Qwen weights to `python3 scripts/qualify_workshop.py --runtime PATH --model PATH --output NEW_DIRECTORY`. Add `--browser` with Playwright and Chromium installed to exercise live model dispatch and export from the browser. Add `--study` to compare the old and proposed builder guidance on two separately frozen task contracts. It also runs equal-content, artifact-only and no-inheritance arms. The study records ties, failures and unknown costs and has no promotion authority.

## Français

1. Décompressez l’édition complète. Lancez le programme de votre plateforme ou utilisez `python3 launch.py`. L’adresse locale affichée ouvre l’espace de travail et son connecteur privé.
2. Dans **Paramètres de connexion au modèle**, connectez un modèle qui s’exécute localement. Revenez à **Commencer → L’atelier des instruments**. Sélectionnez le modèle et confirmez la transmission des données pour cette mission.
3. Décrivez votre ambition. Choisissez **Fonderie d’instruments** pour les trois capteurs, **Vérification avec sources** pour le contraste selon les WCAG ou **Conception partagée** pour les coûts et la participation hypothétiques. Pour votre propre tâche, décrivez les entrées et résultats dans les **Détails de la mission** et fournissez des exemples JSON indépendants. Un outil de préparation de commande pourrait recevoir les quantités `arrived` et `reserved`, puis produire `ready` et `remaining`. Prévoyez des exemples de pénurie, d’égalité et de surplus.
4. Sélectionnez **Construire et tester**. **Mission** présente la décision et la question à trancher. **Atelier** montre les fichiers exécutables et leurs liens. **Preuves** présente les requêtes au modèle, les événements, les versions, les essais et les échecs. Une requête déjà envoyée peut se terminer après une pause ou une annulation. Rouvrez la mission avant de demander explicitement une reprise.
5. Téléchargez l’instrument et les preuves. Décompressez le résultat et lancez `python3 RUN_WORKSHOP.py check`. Pour une nouvelle entrée normalisée, utilisez `python3 RUN_WORKSHOP.py run ENTREE.json`. Ajoutez `--profile optics`, `--profile pressure` ou `--profile cold` pour un format d’origine. Des exemples figurent dans `PROOF.json`. **Préparer une nouvelle mission de calibration** propose un nouveau jeu d’essais et conserve le lien vers le prédécesseur.

Le site GitHub Pages offre les brouillons et les instruments manuels hors ligne. L’application téléchargeable utilise les mêmes fichiers d’interface avec un connecteur local. Une API configurée exige un accès et un consentement distincts. La facturation de l’API est distincte de celle de ChatGPT. [Facturation OpenAI](https://help.openai.com/fr-ca/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)

Une **preuve manquante** correspond à un essai, une observation ou une dépendance encore à vérifier. Un **travail de preuve** est une tentative de construction et de vérification à portée définie. Le **dossier de preuves** contient l’instrument, les observations, les versions, les essais et leur mode de reproduction. La décision documente l’admission, la réparation, le rejet ou le changement de dépendances. Une nouvelle mission applique ses propres essais avant d’admettre une capacité héritée.

Le dernier groupe de cas sert à la vérification finale. Le modèle reçoit le contrat, l’instrument précédent et les résultats agrégés des essais de développement. Les protocoles intégrés peuvent lui transmettre un petit contre-exemple synthétique de développement. Les cas finaux, leurs réponses et l’évaluateur restent dans le connecteur. La calibration de terrain exige des étalons traçables, des mesures répétées et un régime de fonctionnement qualifié. Le contrôle de contraste couvre un seul critère à partir des observations fournies. Le scénario économique compare des options hypothétiques à partir des données déclarées.
