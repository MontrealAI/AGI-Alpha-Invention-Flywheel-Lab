# Model-driven Upgrade Foundry / Fonderie pilotée par un modèle

The Upgrade Foundry lets an authorized Codex engineering session propose a new source modification within a fixed scope. It is separate from the authored evidence-reuse demonstration. Its first adapter permits changes to `bridge/instruments.py` in an isolated source copy. It does not replace the installed HARNESS.

**Live qualification depends on eligible official ChatGPT/Codex authorization and a working native sandbox.** Contract tests use explicit fixtures. They do not establish a real authenticated model-written improvement. See the qualification matrix before relying on this pathway.

## Controlled sequence

1. **Register.** Enter a bounded objective and the exact authorized Codex model. The service snapshots the current implementation and freezes fresh confirmation cases before construction. The candidate workspace does not receive those instance values.
2. **Construct.** Explicitly authorize source writing. The official Codex adapter must allow isolated workspace writes and pass its sandbox checks. The model may change only `bridge/instruments.py`; other copied source must remain identical. No source change is an unsuccessful construction attempt, not a completed improvement.
3. **Qualify.** Separately authorize execution. Baseline and candidate run in a native sandbox with no model credentials or external network. The host compares returned values against the frozen independent arithmetic oracle and required error cases. Candidate-written PASS assertions have no authority.
4. **Inspect.** Read the actual source change, baseline/candidate/ordinary results, cost records and limitations. Finite correctness does not establish an improvement in performance, generality or complete economic cost.
5. **Activate for isolated research.** Confirm the exact candidate hash and authorize its selection. This selects a retained candidate for explicit sandbox-only calls. It never overwrites the installed interpreter or changes release controls.
6. **Test a new use.** Supply a bounded instrument and inputs to the retained candidate. A caller-provided expected output can be checked, but that is not independent external acceptance or proof of successor advantage.
7. **Rollback or export.** Rollback clears the research selection. After the attempt ends, export the source, protocol, results and source identity. Preserve rejected and blocked attempts accurately.

Model construction, qualification and activation are distinct authorities. A proposed improvement, successful source edit, passing finite contract and general improvement are different claims. The fixed arithmetic oracle tests interpreter behavior; it cannot validate every possible objective entered by an operator.

## Prerequisites and boundaries

- Run the private local connector from a verified package.
- Configure the supported official Codex executable and eligible ChatGPT authorization; see [ChatGPT/Codex setup](CHATGPT-PLAN.md).
- Explicitly enable isolated Codex workspace-write permission for this task. A model response cannot grant it.
- Native sandbox probes must succeed on the host. The service refuses to run candidate code without this boundary. A clean process environment alone is not a sandbox.
- Construction has no release, payment or customer-data authority. Evaluation runs with a read-only source mount and without provider credentials.
- Source changes after qualification invalidate selection. The evaluator, frozen protocol and original implementation remain outside the candidate's permitted edits.

This first adapter covers one interpreter module and a fixed semantic contract. It is not an unrestricted self-modification system. Discovery of valuable new bounded upgrades, genuine live construction and advantage on different external tasks remain separately measured research outcomes.

## Expert API

Use the authenticated loopback connector session; foreign-origin requests are refused. Do not paste session tokens into shared scripts or reports.

| Route | Input / purpose |
|---|---|
| `GET /api/upgrade-foundry/status` | Inspect experiments, selected candidate and qualification scope. |
| `POST /api/upgrade-foundry/register` | `objective`, `model`; snapshot and freeze a new attempt. |
| `POST /api/upgrade-foundry/construct` | `experiment_id`, `authorize: true`; isolated model-driven source writing. |
| `POST /api/upgrade-foundry/qualify` | `experiment_id`, `authorize: true`; independent native-sandbox comparison. |
| `POST /api/upgrade-foundry/activate` | `experiment_id`, `expected_candidate_sha256`, `authorize: true`; select an unchanged qualified research candidate. |
| `POST /api/upgrade-foundry/evaluate` | `instrument`, `inputs`, optional `expected` and `max_operations`; execute only the selected sandboxed candidate. |
| `POST /api/upgrade-foundry/cancel` | `experiment_id`; request cancellation and reject late results. |
| `POST /api/upgrade-foundry/rollback` | `authorize: true`; clear the isolated selection. |
| `POST /api/upgrade-foundry/export` | `experiment_id`; export a finished attempt, never credentials. |

## Français

La Fonderie permet à une session Codex autorisée de proposer une nouvelle modification source dans un cadre précis. Le premier adaptateur limite les changements à `bridge/instruments.py` dans une copie isolée. Il ne remplace pas le HARNESS installé.

Enregistrez l'objectif et le modèle, puis autorisez séparément la construction, l'exécution de qualification et la sélection du candidat. Les cas de confirmation sont figés avant la construction; le modèle n'en reçoit pas les valeurs. Le vérificateur hôte compare les sorties du bac à sable à un oracle indépendant. Une déclaration de réussite écrite par le candidat n'est jamais une preuve.

La sélection d'un candidat qualifié ne l'active que pour des appels explicites en recherche isolée. Une nouvelle utilisation doit être vérifiée dans son propre contexte. Le retour arrière efface la sélection. Exportez les preuves après la fin de l'essai et conservez les échecs ou blocages comme tels.

Cette voie exige une autorisation officielle ChatGPT/Codex admissible et un bac à sable natif fonctionnel. Les tests de contrat avec réponses préparées ne prouvent pas une modification réellement construite par un modèle authentifié. La correction sur des cas arithmétiques finis n'établit ni amélioration générale, ni avantage économique complet, ni réussite commerciale.
