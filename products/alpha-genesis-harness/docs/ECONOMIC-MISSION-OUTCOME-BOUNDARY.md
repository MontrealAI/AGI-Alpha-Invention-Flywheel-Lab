# Ω ALPHA: instrument evidence and beneficiary outcomes

## Why this repair is necessary

The economic discovery path at PR #517 checked literal quotations, distinct outcome
text and agreement between the proposed source ID and a registered contract's
source ID. It then admitted the model's selected contract for construction.
Those checks establish provenance; they do not establish that the contract tests
the proposed outcome.

[LINKAGE218, PR #518](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/pull/518)
demonstrated the difference: a synthetic clinic inventory service could be mapped
to an integer-addition test from the same source. The unchanged original witness
remains a failed semantic-linkage result at its pinned source. This repair does
not edit that historical evidence.

This boundary is a dependency of a consequential Ω ALPHA mission: an accepted
first capability must actually deliver its beneficiary result before it can
support a claim about a second useful capability. A successful unrelated
calculator must not occupy that first milestone.

## Default behavior

Discovery may propose an outcome, cite evidence and nominate a registered test.
When only those checks support the mapping, the decision now preserves the
hypothesis with:

```json
{
  "selected": null,
  "disposition": "outcome_contract_linkage_unverified",
  "outcome_linkage": "not_established"
}
```

The existing workflow finishes in `needs_review`, with no builder call or
retained artifact. A separate citation pass may repair a citation; it cannot
approve the outcome-to-test link. The model cannot add an approval or scope field
to grant itself authority.

This is a withholding of unsupported admission. It does not prove that the
hypothesis is false, that the proposed test is irrelevant, or that the desired
outcome is impossible. No general semantic evaluator is implemented by this fix.

## Explicit technical qualification

For a fresh, prospectively frozen calculation experiment, the operator may set:

```json
{
  "economic_mission": {
    "qualification_scope": "registered_instrument"
  }
}
```

This fragment belongs inside an otherwise complete mission specification. The
equivalent public-record CLI option is `--instrument-only`. It permits the
existing declarative constructor, development cases, candidate sealing and
withheld qualification to run. It does not admit the proposed beneficiary
outcome. The terminal path independently enforces this scope.

| Reported item | What it can establish |
| --- | --- |
| `INSTRUMENT_CONSTRUCTION` | A constructed instrument was frozen for qualification. |
| `REGISTERED_INSTRUMENT_ACCEPTANCE` | Its outputs passed or failed the frozen qualification cases. |
| `qualification_scope.kind` | `registered_instrument_cases`, with outcome linkage still unestablished. |
| All existing invention, economic and compounding verdicts | `not_established`, on both technical success and failure. |

The instrument's primary registry title identifies the registered contract;
the original ambition remains `mission_objective`. The model's outcome and the
operator's goal text are not used as a qualified capability description. A
service-sounding title cannot transform arithmetic cases into a service test.

Scope follows the result through inspection, history, verification events,
exports, capability listings, reuse, inheritance provenance, CLI summaries and
portable replay. The English/French interface shows the distinction alongside
completion. Inheritance still imports artifacts, never acceptance authority.

Historical completed archives may be replayed against their pinned portable
evaluator. The new replay result describes case-level instrument evidence and
does not rewrite the input archive. Current runtime reuse still requires current
source identity; replay does not bypass that check.

## Evidence and reproduction

The focused regression suite uses synthetic sources and authored model replies;
it makes no model-service requests. It covers unrelated outcome nominations,
blind discovery, copied outcome/goal wording, forged authority, valid and failing
technical qualification, hidden answers, restart, export, registry, inheritance
and historical archive shape.

From `products/alpha-genesis-harness`:

```sh
python3 -B -m unittest tests.test_economic_outcome_boundary tests.test_economic_mission -v
```

The source-bound [compact receipt](../evidence/ECONOMIC-MISSION-OUTCOME-BOUNDARY.json)
records the original counterexample, repaired behavior and executed checks.
Fixtures establish software behavior. They do not establish autonomous invention,
beneficiary adoption, full-cost advantage or realized revenue.

New qualifier receipts call fresh inputs to the same formula
`fresh_instance_reuse`; the old `fresh_transfer` receipts remain unchanged.
Neither is construction of a different second capability. The larger foresight
and successor work must supply an independently adequate outcome-specific test,
useful delivery and a matched comparison before claiming those achievements.

## Compact learning

**Tried:** source identity plus a second model's proposed contract mapping.
**Observed:** the mapping admitted an unrelated outcome under an arithmetic test.
**Changed:** default admission is withheld; explicit instrument trials retain
their useful sealed checks under a technical scope.
**Next:** connect a consequential beneficiary outcome to an independently adequate
executable evaluator. Do not replace that evidence with another approval flag,
matching label, hash or model assurance.
