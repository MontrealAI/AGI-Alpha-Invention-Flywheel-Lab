# Customer mission: portable calibration, with the ordinary route allowed to win

A cooperative of three small laboratories wants to compare measurements recorded by a sensor whose raw scale does not match the shared reference scale. The required result is an inspectable conversion instrument, an independent acceptance procedure, and a decision about whether to build a new coordination workflow or use an ordinary shared service.

This is an **authored synthetic customer exercise**, generated by an included assistant from the objective below during product development. It is neither an observed customer engagement nor a physical calibration, regulatory certification, live model-API run, market-demand study, or admitted Blue Sky flagship. The calibration values and monetary inputs are invented teaching data. The proposed instrument was not selected from the application's demonstration menu. That establishes only that the import/execution path can accept an externally proposed artifact; it does not establish scientific novelty or autonomous discovery by the HARNESS.

## Objective supplied before construction

> Make readings from the supplied sensor comparable with a shared reference. Keep the measurement and its provenance inspectable. Reject a consequential arithmetic defect. Investigate a voluntary arrangement that small participants can afford, and retain an ordinary solution whenever it achieves the same outcome at lower complete cost.

Supplied evidence: raw reading `100` corresponds to reference `0`; raw reading `500` corresponds to reference `10000`. Reference values use integer milli-units. The **declared model assumption** is an affine relationship throughout the closed interval `[100, 500]`. The two calibration points alone do not establish linearity, stability, measurement uncertainty, or physical accuracy.

The included assistant proposed the conversion `reference = (reading - 100) × 25`, a portable declarative instrument, and a shared reference-service arrangement. Neither the formula nor the economic mechanism is claimed as new knowledge.

## What the customer receives

Open `customer-mission.json` through the app's project importer. It contains the objective, source assumptions, independently inspectable alternatives, proposed instrument and scoped evidence. The bounded interpreter can execute the instrument without installing Python or using an API key. Exporting a project preserves the inputs and artifact so another person can repeat the calculation.

The conversion can be useful as an inspectable numerical component in a customer's own process. Before use with real measurements, the customer must independently establish the actual calibration model, units, supported range and uncertainty. This teaching artifact does not control physical equipment.

## Competing complete routes

| Route | What changes | What the example establishes |
|---|---|---|
| Separate external verification | Each lab obtains its own reference check | An explicitly modeled outside option; no real supplier quote |
| Ordinary shared service | A shared reference plus direct algebra/spreadsheet, with the same permissions and acceptance | Same numerical outputs; lower modeled construction cost |
| HARNESS construction | Imported proposal, declarative instrument, source/evidence record and modeled participation check | Executable and inspectable; no output advantage is assumed |
| Non-entry | No new service or construction | Valid whenever evidence, incentives or funding are insufficient |

The ordinary route is allowed to share equipment, coordinate participants, use the same formula and construct its own verifier. It is not artificially restricted to isolated work or a weak algorithm.

## Executed result and reproduction

The product's bounded interpreter executed raw reading `340` as `{reference: 6000, inRange: true}`. The four exposed development cases all agreed with the ordinary direct calculation. Their verification remains `UNKNOWN` because the mission author prepared them. The planted offset omission was `REJECTED`. The composed construction/execution/economic workflow completed, all four modeled participants met their outside options, and capability search selected `ordinary-shared-route` at $300 rather than the $330 HARNESS construction.

From the extracted product directory, developers can repeat the substantive calculation with Node.js:

```bash
node - <<'NODE'
const fs = require('node:fs');
const assert = require('node:assert/strict');
const E = require('./app/engine.js');
const p = E.importProject(fs.readFileSync('./examples/customer-mission.json', 'utf8'));
const artifact = E.constructInstrument(p.instrumentSpec);
assert.deepEqual(E.executeInstrument(artifact, p.instrumentInput).outputs,
  {reference: 6000, inRange: true});
for (const c of p.confirmation.cases) {
  const reading = c.input.reading;
  const ordinary = {reference: (reading - 100) * 25,
    inRange: reading >= 100 && reading <= 500};
  assert.deepEqual(E.executeInstrument(artifact, c.input).outputs, ordinary);
}
const frozen = E.freezeConfirmation(p.confirmation);
assert.equal(E.verifyInstrument(artifact, frozen).verdict, 'UNKNOWN');
assert.equal(E.verifyInstrument(E.constructInstrument(p.plantedInstrumentSpec), frozen).verdict, 'REJECTED');
const economics = E.evaluateArrangement(p.arrangement);
assert.equal(economics.verdict, 'PASSED IN SCOPE');
assert.equal(economics.totalCostMinor, 33000);
assert.equal(economics.savingsMinor, -3000);
assert.deepEqual(economics.participation.map(x => x.netBenefitMinor), [46000,46000,46000,9000]);
console.log('Repeatable numerical artifact; ordinary alternative wins modeled cost comparison.');
NODE
node --test tests/acceptance.test.cjs
```
