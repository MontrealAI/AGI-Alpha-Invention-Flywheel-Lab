# Instrument workshop qualification

Each execution records the product source, input contract, model route, outputs and remaining scope. Read the exact-source release receipts before assigning a release verdict.

| Requirement | Implementation | Acceptance or replay | Scope |
|---|---|---|---|
| Versioned mission, one state and recoverable execution | `bridge/workshop.py` projects `WorkflowService` state | `tests/test_workshop.py`, `test_workflows.py` | Stable registration identity, revision-checked controls, cancellation and late-result refusal. Separate workspace roots for separate operators. |
| Bounded construction and evidence | `bridge/instruments.py`, `bridge/workshop_protocol.py` | Formula boundary tests, independent final cases, exported `RUN_WORKSHOP.py check` | No shell, arbitrary Python, network or file access in candidate formulas. |
| Source, scope and revocation | `current_evidence`, `require_compatible`, `revoke` | Loaded dependency replaced before first workshop call, different workspace, revocation and fresh cases in `test_workshop.py` | Admission requires the original loaded identity to match the live files and recorded evidence. A successor must pass fresh checks. |
| Instrument Foundry | Three native adapters and one model-built formula instrument | Frozen raw observations and standard-library regression plus exact interpolation in `PROOF.json` | Software calibration on synthetic observations. No physical or general performance claim. |
| Source-grounded instrument | Pinned WCAG contract and separate cases | Exact threshold, stale criterion, plausible exceptions and review cases | Measurements and classifications are supplied. |
| Technical and economic screen | Frozen conditional arrangement contract | Cost tie, withdrawal, liquidity, rights, privacy and cost-overrun cases | Assumed costs and choices. No funds, transactions or external commitments. |
| User-authored mission | Custom input/output contract and separate case material | Native mission execution with independent examples | New instruments within the formula language. Unmodeled tasks require another authorized extension. |
| Model identity and repair | Loopback model connector and immutable workflow events | Actual completion, raw model response, failed attempts, standalone replay | Fixture, local and configured API evidence are distinct. Authenticated frontier access requires separate evidence. |
| Bilingual browser, connected and offline modes | `app/workshop.js` and existing origin/session boundary | Rendered-browser receipt, export, reload, keyboard and narrow viewport checks | Report the browser and OS exercised. GitHub Pages runs the offline mode. |
| Exact download and live site | Existing archive build, Pages publisher and release workflow | Match archive checksum, source version, committed public files and deployed URL | Local builds and PR checks alone do not establish public deployment or published-byte operation. |
| Retained-method and recursive builder superiority | Existing GENESIS NEXT comparisons and `scripts/workshop_builder_study.py` | `qualify_workshop.py --study` runs frozen dispatch and handover cases with matched local model, tools and budgets | The experiment is runnable. Method advantage and complete-cost superiority require observed results and stronger replications. |
