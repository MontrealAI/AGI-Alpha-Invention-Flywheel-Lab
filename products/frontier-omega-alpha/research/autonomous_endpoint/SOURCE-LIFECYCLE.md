It names a non-admin provider UID distinct from the owner, evaluator and constructor, a protected private `publisher_state`, the exact SHA-256 of the administrator-owned `approved-source-adapter.py`, `max_versions_per_run`, `adapter_wall_seconds` and `interval_seconds`. Its public digest must match the approved source fingerprint and differ from the evaluator’s. The offline owner key stays with the owner. The actual source adapter, signed grants, input paths and operator identities remain in the controlled host environment.

## The unattended data path

| Role | Routine operation |
| --- | --- |
| Approved source adapter | A pinned read-only program automatically collects the source’s eligible versions and emits one bounded JSON list. It performs the source-specific rights and eligibility checks under its approved identity. |
| Publisher | Runs the adapter as the non-admin source UID, bounds wall time and output, validates fixed scope, requirements, payload limit and retention. It signs an `input-version.json` and commits one content-addressed directory under a private outbox. Repeat delivery of the same signed version is idempotent. |
| Independent stager | The administrator-owned service checks the actual host canary and unchanged signed approval. It takes bounded file-descriptor-based snapshots, rejects nonregular files and path redirection, verifies the publisher signature and exact content hashes, then atomically stages root-owned read-only bytes. This role executes no adapter code. |
| Evaluator | The approved service scores each eligible version once under the standing lease. Cases stay private. The only release is an aggregate bound to the authority and input fingerprint. |
| Retirement | Routine wakes remove only authenticated, expired managed snapshots within the approved outbox or staged queue and expire evaluator-owned copies under its existing policy. A still verifiable expired lease can dispatch retirement only. Key rotation and changed rights require the owner to retain the applicable cleanup authorization for the old scope. |

Adapter entries have schema `frontier-omega-alpha/source-output-v1`, `scope_id`, a stable `source_revision_sha256`, source-bound `valid_from` and `valid_until`, and a `records` map of plain filenames to base64 bytes. Include the exact approved requirements file and eligible records. Use stable source versions, not fresh timestamps on unchanged inputs. A failed source returns no newly eligible version or a source-side failure for the next scheduled wake. The root stager never follows a mutable file pointer into a different source folder. Exact signatures and approved scope control admission.

After the existing canary passes, the actual host administrator can render the two fixed service definitions with `record_intake.py plist-produce` and `record_intake.py plist-stage`, using the same `--authority-root` and independent `--owner-pin` as the evaluator. Install them once alongside the approved evaluator job. Neither render command installs or starts a service. Run the scheduled producer as the approved publisher UID and the nonexecuting stager as the independently controlled administrator. The recurring cycle has no form, human case selection or new approval for unchanged scope. The grant does not authorize choosing new sources, expanding the approved records or changing requirements. Follow the existing key revocation and service disable procedure in [CUSTODY.md](CUSTODY.md).

The off-host tests ran one source subprocess, sealed two existing signed public research receipts, staged both through the portable bounded copy and verification path, proved idempotency, rejected tampered requirements, removed the two expired copies in a temporary store and preserved an unrecognized directory. The live Mac launcher refused off-host activation. Actual Mac administrative separation, live source grants and private records remain pending.
