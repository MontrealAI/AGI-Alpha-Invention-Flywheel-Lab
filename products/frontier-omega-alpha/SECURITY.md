# Security design and review / Conception et revue de sécurité

**Current GitHub-only release path.** See [GitHub Pages and MetaMask](GITHUB-NATIVE.md) for native provisioning, isolated hosting, bilingual instructions and the current threat model. The original SIWE access service remains the local reference.

## English

The Pages artifact is public. Its allowlist contains only the authored landing assets, a blank API configuration and client decryption code. The access service stores releases in private SQLite. It authenticates a wallet, checks current membership or holdings, and returns either one AES-256-GCM content key with its ciphertext or server-decrypted bytes for one release. The AES-GCM associated data includes scheme, asset identifier, version, key epoch and format. Key wrapping uses a separate KEK and authenticated domain with fresh 96-bit nonces. The KEK never crosses the reader API.

| Trust boundary | Control and residual |
| --- | --- |
| Wallet forgery, wrong domain and signature replay | The server constructs the exact EIP-4361 message. Domain, URI, selected label, Ethereum mainnet and a two-minute nonce are signed. SQLite consumes the challenge once, including under concurrent use. A deployed contract wallet is checked via EIP-1271 on sign-in and each protected read. Deployed wallets lacking that interface require a compatible signer flow. |
| ENS aliases, transfer, wrapping or expiry | Mainnet ENS Registry `owner` for the exact ASCII one-label name from GoalOS v2.0.0-SO2. For the official Name Wrapper, `ownerOf` and `getData` must agree and a nonzero expiry must be in the future. Resolvers and operator approvals provide no entitlement. |
| Token spoofing or lost balance | An immutable address, live code, `AGIALPHA` symbol, 18 decimals and integer `balanceOf` threshold. Each protected operation freshly rechecks available paths. Token eligibility is independent of AGI Club ownership. |
| Wrong network, stale RPC or reorg | The configured RPC must report chain ID 1 and a head no more than 90 seconds old. Reads use a common canonical block hash via EIP-1898. A failure prevents issuance absent a separately confirmed path. The trust model assumes an honest RPC and a working clock. A reorg after a valid check cannot undo a completed release. |
| Session fixation, theft, abuse and CSRF | A random 256-bit bearer lives in page memory and the server stores its hash. Exact Origin and content-type checks, CORS without credentials, five-minute expiry, per-route rate and concurrency limits, revalidation before protected operations, user lock, wallet-event lock and operator revocation. Bearer theft permits replay until revocation, expiry or confirmed loss. Edge controls are required for production shared or high-traffic deployments. |
| Plaintext, source map and key leakage | No protected values or source maps in the Pages allowlist. Private state and keys are owner-only, API responses use no-store and JSON, and public routes send no secrets. The operator must keep private storage, reverse proxies, backups and infrastructure logs outside public artifacts. Already displayed bytes can be copied. |
| Unauthorized API, tenant leakage and privileged execution | One reader catalog of expressly approved releases. Guessing an asset ID provides no access. No member write, upload, administrative, commerce or command execution route exists. The operator CLI and research runtime are separately authorized by private filesystem/host ownership. |
| XSS, prompt injection and supply chain | Browser inserts localized text using DOM text properties. Links require HTTPS and no opener/referrer. Static CSP denies inline execution and arbitrary network destinations. The ingestion layer reads bounded, allowlisted source text as data. Dependencies and CI actions are pinned, with package review during qualification. A compromised publisher or any script served at the configured web origin has significant reach. |
| Metadata, privacy and operational failure | No wallet analytics are included. The service needs the public wallet, optional Club label and signature for verification, and retains contract signatures only for the short session. SQLite expiry cleanup and secure deletion reduce retention. Operator backup, log and privacy policies must cover remaining copies. Wrong epoch, missing key and authoritative state failures block the protected API. |

The GoalOS reference reviewed was [the published v2.0.0-SO2 access script](https://montrealai.github.io/goalos-singularity-office-omega/access.js), SHA-256 `3106ef034ba955d5cc9703df36235859200e65360f39c5228d05025fa6a49d40`. Standards and network references include [ERC-4361](https://eips.ethereum.org/EIPS/eip-4361), [ERC-1271](https://eips.ethereum.org/EIPS/eip-1271), [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898), [ENS Name Wrapper](https://docs.ens.domains/wrapper/contracts/), and [NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final).

The automated adversarial checks exercise the deployed HTTP route shape with synthetic wallets and RPC state. Direct read-only mainnet verification established the token metadata and capability to read by canonical block hash. A reviewer independent of this implementation still needs to assess the exact deployed frontend, API, upstream RPC, legal/privacy obligations and key custody before protected access is enabled.

## Français

Le site Pages est public. Sa liste d’autorisation contient les fichiers de présentation, une configuration d’API vide et le code de déchiffrement. Le service conserve les dossiers dans une base SQLite privée. Il authentifie le portefeuille, vérifie l’admissibilité actuelle et livre le fichier chiffré et sa clé AES-256-GCM ou le dossier déchiffré côté serveur. Les données associées lient le schéma, l’identifiant, la version, l’époque de clé et le format. Une clé d’enveloppe distincte et des nonces de 96 bits protègent les clés de contenu. La clé d’enveloppe ne transite pas par l’API.

| Risque | Contrôle et limites |
| --- | --- |
| Usurpation de portefeuille, domaine erroné ou rejeu | Le serveur crée le message exact EIP-4361. La signature lie le domaine, l’URI, le libellé demandé, le réseau principal et un nonce de deux minutes. SQLite consomme le nonce une fois, même en cas de requêtes simultanées. Un portefeuille contractuel déployé est vérifié selon EIP-1271 à la connexion et aux lectures protégées. |
| Alias ENS, transfert, enveloppement ou expiration | Le registre ENS du réseau principal identifie le propriétaire direct du nom exact conforme à GoalOS v2.0.0-SO2. Pour le Name Wrapper officiel, `ownerOf` et `getData` doivent concorder, et une date d’expiration non nulle doit être future. La résolution et la délégation ne donnent pas accès. |
| Faux jeton ou perte du solde | L’adresse est fixe. Le code, le symbole `AGIALPHA`, les 18 décimales et le seuil entier via `balanceOf` sont contrôlés. L’admissibilité est recalculée avant les opérations protégées et peut être établie sans AGI Club. |
| Mauvais réseau, RPC périmé ou réorganisation | Le RPC de confiance doit indiquer la chaîne 1 et un bloc de tête datant d’au plus 90 secondes. Les lectures utilisent le même bloc canonique selon EIP-1898. Si la vérification échoue, seul un autre accès vérifié peut autoriser la lecture. Une réorganisation peut intervenir après une délivrance. |
| Fixation ou vol de session, abus et CSRF | Jeton de 256 bits conservé dans la mémoire de la page, avec son empreinte côté serveur. Contrôle strict d’origine et de type de contenu, CORS sans identifiants, expiration de cinq minutes, limites de débit, contrôles renouvelés, verrouillage au changement de portefeuille et révocation par l’opérateur. Un jeton volé est utilisable jusqu’à sa révocation ou son expiration. |
| Fuite de texte, de code source ou de clés | Aucun contenu protégé ni fichier source map dans le site Pages. Le serveur répond en JSON sans mise en cache. L’accès disque est privé. Les sauvegardes, journaux et composants intermédiaires relèvent de l’exploitant. Les octets affichés peuvent être copiés. |
| API non autorisée, cloisonnement et exécution | Le catalogue en lecture contient exclusivement les dossiers approuvés. Un identifiant deviné ne donne aucun accès. Aucune route membre ne permet de téléverser, publier, exécuter ni effectuer une transaction. Les opérations internes dépendent d’autorisations distinctes sur l’hôte et le système de fichiers. |
| XSS, injection dans les sources et dépendances | Les données de recherche sont insérées comme texte. Les liens HTTPS isolent la fenêtre cible et n’envoient pas de référent. La politique de contenu limite les scripts et connexions. L’ingestion traite les sources textuelles autorisées comme des données. Les dépendances et actions sont fixées à une version. Une compromission de l’éditeur ou d’un autre script sur la même origine nécessite une intervention. |
| Métadonnées, vie privée et panne | Aucune analyse des portefeuilles n’est intégrée. L’adresse publique, le libellé facultatif et la signature servent à l’authentification. Les signatures contractuelles sont conservées dans l’état SQLite privé pendant la session courte. Le nettoyage et la suppression sécurisée réduisent la rétention. Les sauvegardes et journaux exigent une politique d’exploitation. Une clé ou un état incohérent ferme l’accès. |

Les tests utilisent des portefeuilles synthétiques et un Ethereum simulé. Une lecture seule sur le réseau principal a confirmé l’identité du jeton et la lecture par empreinte de bloc canonique. La revue indépendante de la version déployée, du fournisseur RPC, des obligations de confidentialité et de la conservation des clés reste nécessaire avant l’activation de la zone protégée.
