## 4. A second probe: separate the outcome from a single cleanup scope

The second beneficiary-oriented question concerned transactional streaming services: can a service avoid reporting success before a transaction is durable while keeping the resource live until streaming completes? ## 5. Executable construction and supplied knowledge

### 5.1 What was constructed

The campaign implemented a bounded effect-factorization compiler and capability interpreter. The supplied semantics identify five roles: acquire a resource, prepare data, make data durable, consume while live, and release. A task lists typed operations, a shared resource, compound blocks and an explicit permission stating which blocks may be separated. The compiler infers role correspondence from those typed operations rather than lexical similarity, searches block permutations, and, where authorized, separates compound effects. It produces a source-bound plan and a generative factor operator.

This is executable adaptation rather than a fixed menu of complete programs. Nevertheless, its operation semantics, donor pattern, role constraints, finite grammar, factorization permissions and search procedure were supplied by the development model. No mathematical novelty, autonomous discovery of the donor, broad scientific invention or beyond-human foresight is claimed. Changing a nonseparable block to separable without authority is rejected; that would change the permissible problem.

The real SQLite-stream construction used deliberately misleading operation identifiers. The compiler mapped their supplied operation semantics, split the permitted commit/close block, and found the required order after 140 attempted arrangements. The mapping influenced the actual plan and adapter. Failed arrangements remain in the construction report.

### 5.2 Actual FastAPI adapter

The generated plan was not left as static metadata. An adapter divided its operations around the consume effect, executed the before-consume portion through a real dependency, streamed from SQLite, and executed cleanup at request exit. Its four development cases covered successful delivery, actual deferred commit failure, a failure after the first emitted chunk, and an injected interruption after the first chunk. All four passed the bounded trace contract. Partial output was explicitly excluded from full-delivery acceptance.

These cases measured a local ASGI send boundary and actual database behavior. The injected interruption is not an operating-system cancellation experiment or proof of a real network disconnect; Starlette may translate it into its disconnect exception. The adapter's installed packages were FastAPI 0.162.0, Starlette 1.10.0 and Pydantic 2.14.2. Its development execution took 0.759 wall seconds and 0.473 process CPU seconds, with peak RSS 36,668 KiB. Setup and full monetary costs are separate.

### 5.3 Runtime restrictions

Generated plans execute in a restricted interpreter over at most five whitelisted effects and 64 bounded string values. Plans cannot contain Python, shell commands, dynamic imports, network access or caller-selected filesystem paths. Real SQLite and file handles are created inside temporary directories by fixed trusted operations. Plan, specification and applicability identities are checked before effects execute. This is a bounded capability interpreter; static validation alone is not presented as runtime execution, and the trusted host programs are not claimed to be a general sandbox for arbitrary code.
