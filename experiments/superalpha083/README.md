# Super Alpha 083: reject the codec as a Blue Sky flagship

**Executed 3 November 2026.** A working XOR codec and exact recovery compiler were built and tested. The experiment did **not** find a newly possible productive activity, an enormous complete-cost advantage, a new industry, or an earned-capital path to $3 billion. Strong ordinary locally recoverable codes already deliver the entire requested recovery service. Retain the small implementation and the selection lesson; do not expand this codec campaign as the flagship.

## What actually ran

The fixed contract stores eight data shards as fourteen equal-size shards in racks of 5/5/4. Every implementation must recover all 469 nonempty erasure patterns of size at most three, and each complete rack loss, for 472 registered patterns. Corruption, Byzantine failures, correlated failures outside this contract, network service levels and production deployment are not covered.

The authored constructor searched six binary parity masks and placement using 24 starts and 400 proposals per start. It is ordinary deterministic randomized search, not demonstrated autonomous algorithm invention. The selected masks are `[33, 204, 71, 60, 222, 183]`. The encoder and decoder operate on actual bytes. An independent polynomial-arithmetic verifier checks field multiplication, all subset ranks, helper witnesses, byte encodings/decodings and the successor outputs.

Each of seven implementations recovered **28,320 source-byte cases with zero errors**, across the same 472 failures, twenty seeds and three shard sizes. There are no customers in this denominator. The original four-method run took 28.76 seconds, including 5.34 seconds for candidate search; the stronger three-baseline/reliability supplement took 22.42 seconds. These are one-host execution telemetry, not independent timing trials or total business costs.

Every method passed the originally chosen rack layout. Fresh layouts were fixed unseen reconfiguration challenges, not a measured distribution of actual rack failures. The ordinary pair-local code reads fewer helpers on average. The constructed code has a smaller worst helper count but worse 4-loss and layout robustness. These are **different tradeoffs, not dominance**. Fixed n=14/k=8 is a bounded falsification probe, not a market-derived customer specification.

Helper minima are exact for full-shard linear recovery without subpacketization. Supplementary repair programs actually execute those witnesses: fourteen single-loss repairs across the same sixty byte inputs, 840 cases per method. Original `recovery_seconds` measures eight-shard full-source recovery, not minimum-read repair latency; supplementary timing is labeled separately. Neither is network throughput. We did not execute vendor production binaries, cache/subpacketized schemes or all known optimized LRC implementations, so no state-of-the-art claim is made.

## Why this does not satisfy Super Alpha

The same newly proposed service was already feasible with ordinary LRC. More agents, a synthesized matrix, lower repair counts on some losses or a new report do not change that fact. Complete alternatives can choose the best reliability/locality tradeoff, not just the first baseline we wrote. The primary competent-human-with-software versus frontier-agent full-lifecycle productivity comparison was not measured.

The GF(2) successor reuses the code for distributed binary matrix-vector evaluation. Both the constructed XOR code and the conventional Hamming code produced the exact direct-reference result in **4,720 failure cases each**. This demonstrates a different computational use of an existing linearity property. It does not demonstrate a new coding-computation capability, better discovery, a successor inaccessible to ordinary reuse, or a profitable invention flywheel. Encoding, full worker compute, scheduling and recomputation economics remain unmeasured.

## Prospective record and deviations

The initial protocol was published before implementation/outcomes at [`3c1c57d5`](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/commit/3c1c57d5352e949513673d9b0f041e9933f60fe2). The original `RESULT.json`, `codec.py` and `run.py` remain unchanged. Stronger comparison was then registered at [`e06d4996`](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/commit/e06d49965b9af4c44cfe289b40fe822f678443ae); the two additional baseline formulas and executed minimum-read repairs were added to the local supplement before supplementary execution, with publication afterward. Supplement results are adversarial follow-up, not original confirmation.

Independent review identified three original protocol gaps:
- Final states of all 24 starts were saved, but the full proposal/failure/incumbent trace was not. The 9,600 proposal limit is in source, not an independent execution ledger.
- Tie-breaking is lexicographic, not a measured lower-complexity criterion.
- Candidate placement was jointly mutated while controls got 9,600 dedicated placement proposals. Actual placement opportunities are not equal. This cannot support a controlled causal advantage claim.

No thresholds or original results were changed to hide these deviations. The initial independent verifier recorded source-fingerprint mismatches rather than making them fatal; that was corrected before publication. The final verifier fails closed before importing changed code, rejects Python optimization that would disable assertions, and passes deliberate-corruption tests. `REVIEW_HISTORY.json` preserves the initial source/receipt identities. The independent verifier has its own exact-source qualification; review is procedural independence on a shared host, not external certification.

No actual customers, revenue, spending, outreach, API/Platform calls, API keys, native account, financing, or deployment. Actual total model/host billing is unknown, not zero. No simulated sales or profit were invented. The requested $100,000 primary-challenge seed is not opened or spent, and **$3 billion trailing-365-day complete-cost profit remains unestablished**.

`COSTS.json` lists required economic categories explicitly. Research, failed construction, acquisition, integration, maintenance, security, operations, support, financing, taxes, reliability obligations and market uptake are unpriced. A byte-correct codec supplies neither voluntary paying demand nor economic capture. An annual sales forecast would therefore be an assumption rather than an observed or native-accounted result. The economically justified decision is no flagship promotion and no financed rollout on this evidence, not a claim of universal impossibility for storage businesses.

## Selection and prior art

- Passive joint holding/sliding surfaces: actual public data/code were inspected, but transferable jointly selectable contact-family calibration was not established. The [Fu et al. study](https://arxiv.org/html/2605.19555v1) describes separate calibration steps, including device-level friction-stress fitting. We did not execute or claim a qualified mixed surface. Public source: [Zenodo 22142148](https://doi.org/10.5281/zenodo.22142148), CC BY 4.0.
- Original-requirement industrial planning: the lab's [Operational075](https://github.com/MontrealAI/AGI-Alpha-Invention-Flywheel-Lab/pull/164) already executes this construction class; repeating it would not establish a new activity or solve demand.
- Rack-aware exact coding: selected for a genuine executable output rather than a physical simulation proxy, then rejected as Blue Sky because complete conventional alternatives already supply it.

[Google's Uniform Cauchy LRC study, FAST 2023](https://www.usenix.org/system/files/fast23-kadekodi.pdf), supplies important all-symbol-locality and reliability comparisons. Our small algebraic implementation is not its deployed cluster experiment. [UniLRC, 2025](https://arxiv.org/abs/2505.06819), explicitly combines topology, local coding and reliability. Its stated unmodified family does not have n=14,k=8; adapted/shortened forms were not tested, which remains a comparison limitation rather than a reason to ignore it. No global novelty or exhaustive best-opportunity claim follows from this bounded search.

## Reproduce

Use Python 3.12 and NumPy 2.3.5. From this directory, run `python independent_review.py --supplement` to audit saved original and supplementary evidence, then `python -m unittest -v test_independent_review.py` for five tests including seven deliberate-corruption probes. To reproduce construction, copy the directory to a fresh temporary location and run `python run.py` followed by `python supplement.py`, then audit the new results. Do not overwrite the committed original evidence. Timings will differ; mathematical results are the comparison target.

The scoped workflow audits saved evidence and reproduces in a temporary copy. Hosted receipt, merge, release, physical/system deployment and commercial admission are separate statuses. This draft does not authorize or claim any of them.
