# Preconfirmation schema correction

Independent static review, before any registered confirmation execution, identified two validation defects: a NaN `linearization_scale_m` escaped comparisons, and two truthy strings could masquerade as consent. The amended input gate requires a finite scale and two explicit Boolean true consent values. The execution-default flag also receives a strict Boolean type check. These changes narrow admitted malformed input without changing scientific thresholds or random seeds.

Before confirmation, an internal protocol audit also distinguished disclosed quoted costs from actual private participant costs. A separate participant-response function now sees the actual type only after the fixed offer, may refuse before payment, and never requotes after that response. Three prospective B cost types (12,000, 300,000 and 1,000,000 USD per m/s) test understating the disclosed rate. The preregistration adds those three cases and clarifies that quote-grid optimality is not Bayesian incentive compatibility or truthful revelation. These edits were in progress while the parent froze the first source; the new complete source/preregistration must therefore be frozen together before execution.

No confirmation outcomes had been observed. The initial frozen source and preregistration remain in Git history; the parent integration owner freezes this correction before the first registered execution. These are prospective implementation corrections, not repaired scientific performance or a rerun of a failed seed. Shared-host procedural verification is not external certification.
