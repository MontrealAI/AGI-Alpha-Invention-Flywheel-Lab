# Ω.001 — operator and presenter script

## Before doors open
- Rehearse on the actual presentation computer, with Python 3.10+ and the exact extracted ZIP.
- Open the strongest currently selectable Pro reasoning model. Record actual label and mode. Do not advertise an unverified model name.
- Confirm screen sharing shows no credentials, private chats or unrelated files. Use fictional input only.
- Freeze builder-visible contract and evaluator cases separately. For a fresh independent claim, ask an evaluator who does not implement the candidate to generate and hash additional cases before receiving the candidate. Supplied kit cases are already disclosed.
- Keep prepared fallback ready and visibly labeled. Do not require Internet for fallback. Agree on a six-minute construction cutoff.

## 0–10 · The revelation
“The question is not whether a model can add three numbers. It is whether we can turn a proposed new arrangement into a testable instrument, challenge its assumptions, and retain something useful.”
Show individual caps 120/160/220 versus project450. Ask whether impossible alone means impossible collectively. Reveal 90/140/220 only after predictions. State all values and consents are hypothetical.

## 10–23 · The attempt
Use CHATGPT-PRO-BUILDER prompt. Show the contract, save the model response and record actual model/mode. Freeze candidate; import and test. Explain that the trusted interpreter executes restricted formulas and the adapter enforces input types. Model-created formulas are not trusted on reputation.
If six-minute limit reached: switch to prepared reference and name it as such. Preserve incomplete attempt, never simulate a live response.

## 23–35 · The challenge
Council chooses consent withdrawal, cap breach, or cost beyond collective capacity. Run the corresponding input. An honest refusal is a useful outcome.
If actual candidate fails: preserve failure, give bounded feedback, save a separate repair and retest. Previously revealed cases are no longer held out.
If candidate passes: demonstrate `missions/total-only-fault.json` with `--instrument`, explicitly calling it an intentional fault injection. Never call it a spontaneous model mistake.

## 35–43 · Retain and reopen
ZIP the whole kit/candidate and save its checksum. Extract to another directory, execute `fresh-reopen.json`, then inspect the output. Ask what survived: explicit contract, executable check, tests and caveats. Not the model session or a commercial business.

## 43–55 · Judgment
What assumptions were declared? Which consent or cap changes make the arrangement invalid? Which new constraints would require a new instrument? What evidence would justify use beyond fictional arithmetic?
Distinguish construction, independent testing, retained artifact reuse and improved discovery. This demo establishes none of the latter's broad causal claims.

## 55–60 · Next frontier
Invite a fresh bounded question with measurable outputs and independent checks. End with the reusable artifact and failed cases, not an unsupported superintelligence claim.
