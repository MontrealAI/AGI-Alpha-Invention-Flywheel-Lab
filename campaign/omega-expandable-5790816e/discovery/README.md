# Stronger specialist discovery and scale screen

The public specialist performs the same accepted authored work with fewer oracle
calls. This is a diagnostic on the three already exposed four-state protocols,
not unfamiliar equipment, fresh scientific confirmation or market evidence.
It changes the next construction decision: consider the established specialist
for a subsequent edition, and withdraw any claimed learning advantage. The
registered account, original tie and frozen confirmation source are unchanged.

| Per authored protocol | Registered learner | AALpy L* plus bounded W-method |
|---|---:|---:|
| Learning oracle calls |3,280|144|
| Learning input symbols |21,324|333|
| Unchanged independent checking calls |6,640|6,640|
| Portable-runner smoke oracle calls |1|1|
| All measured oracle calls |9,921|6,785|
| All measured input symbols |65,175|44,184|
| Accepted protocols |3/3|3/3|

The complete measured query path uses **31.6% fewer calls**, about 1.46 times the
query efficiency. Adapter hashes match within each protocol. Learning alone has
a much larger ratio; that ratio must not be advertised as a complete workflow
speedup. Setup, buyer effort, commercial costs and downstream integration were
not measured. Shared-host timings are telemetry, not a controlled speed claim.

The AALpy wrapper receives only the same reset-and-query callable. Its step
interface re-executes the whole current prefix, and counts those extra queries
and symbols. It cannot inspect the target state table. Both arms use the
unchanged original independent checker, then execute the same portable Python
runner against their emitted JSON adapter. The independent reviewer repeated all
six arms and checked rejection of changed checker source. See
[AALPY_QUALIFIED_RESULT.json](AALPY_QUALIFIED_RESULT.json) and
[AALPY_REVIEW.json](AALPY_REVIEW.json).

## Reproduce

Python 3.10 or newer is required by the selected AALpy checkout; the observed
interpreter is recorded in [SPECIALIST_SOURCES.json](SPECIALIST_SOURCES.json).
From this directory, use an isolated environment and an unmodified public
specialist checkout. The commands install free public software; they do not
access any model provider or create financial accounts.

```sh
git clone https://github.com/DES-Lab/AALpy.git AALpy
git -C AALpy checkout --detach 4c7b4a8746460fd84eaccb48d4891e5e0ac90883
python3 -m venv probe-env
probe-env/bin/python -m pip install --only-binary=:all: --require-hashes -r requirements-specialist.txt
probe-env/bin/python aalpy_probe.py --lab-root /path/to/qualified-lab-checkout --aalpy-root ./AALpy --output AALPY_REPRODUCTION.json
probe-env/bin/python scope_screen.py --registration /path/to/qualified-lab-checkout/campaign/omega-expandable-5790816e/REGISTRATION.json --output SCOPE_REPRODUCTION.json
```

The qualified lab source is commit
`6ff45e25a85a590d4921aef6e197148252b92cce`. Reuse an existing isolated checkout
or create a detached worktree; do not reset an active owner's checkout. The probe
enforces the exact compatibility/checker source hash, exact specialist commit,
unmodified specialist worktree, dependency versions and installed Python source
hashes. `scope_screen.py` also accepts `--market-source` when the registration
and source layout differs. Output names are caller-selected; use new names to
preserve original receipts.

The first diagnostic launch failed at import because `pydot` was absent. An
isolated installation of pydot 4.0.1 and pyparsing 3.3.3 corrected setup without
changing methods or cases. The reusable rerun adds source/dependency guards,
explicit smoke counts and telemetry; it does not turn exposed cases into new
confirmation. Setup duration and human effort are unmeasured. No real money or
paid API calls were used; host allocation is not assumed economically free.

## The scale question is separate

The current model globally deduplicates an edition buyer within an authored
100,000-person maximum audience. At the largest listed price, US$599, even 100%
purchase and collection yields at most US$59.9 million gross. That is a structural
non-test of the US$3 billion profit objective, not a measured real market ceiling.

The executed [scope screen](SCOPE_QUALIFIED_RESULT.json) uses exact registered
processing, delivery and hypothetical tax rates. At US$299 it requires at least
**13,985,037 accepted collections**, even before acquisition, failures, setup,
hosting and other costs. This is a necessary lower bound, not a forecast or
native execution. It cannot replace the original account, manufacture a demand
distribution or justify multiplying a short-run margin into an annual result.

## Three next discovery decisions

| Route | Important remaining uncertainty and smallest decisive test | Decision now |
|---|---|---|
| Defined self-hosted software edition | Does packaging an established specialist save enough complete setup/correction effort on an independently specified unfamiliar workflow to beat free self-service? Match prerequisites, acceptance and full buyer effort; allow decline. A specialist tie on the complete path defeats the premium-value thesis. | The stronger specialist diagnostic is executed. Keep ordinary commerce as a possibility; no Super Alpha claim. |
| Jointly commissioned adapter family | Can several voluntary buyers finance one useful common construction with separately accepted adaptations, while ordinary consortium procurement receives the same commitments, rights and funding sequence? Small test: one actual common component and two materially different adaptations, default/withdrawal cases, and equal-content ordinary construction. A conventional tie defeats special arrangement superiority. | No new evidence of a common expensive missing component or buyer commitment was found. Do not repeat an authored pooling win or recognize pledges as cash. |
| Accepted end-to-end compatibility outcome | Is there a specific external workflow that current learning libraries, ordinary migration and existing protocol bindings cannot economically restore because observable semantics, timing or side effects remain missing? First obtain one authorized, independently specified counterexample and its complete baseline; only then construct the missing observation or instrument. If the needed semantics are unobservable under the allowed probes, refuse rather than infer them from trace agreement. | This source screen did not identify a qualified new flagship. Generic reset minimization, stochastic modeling and standard protocol bindings already have strong alternatives. |

For the seller, a separate prospective expansion design should make discovery and
qualification of additional distinct segments an optional funded action. A paid
probe can reveal a scoped supplier opportunity; it cannot directly create buyers
or bypass outside options. Account for overlap, failed qualification, channel
expiry, rival response and liquid cash before admitting the next segment. Preserve
the old fixed-world results and the same primary financial authority. Enlarging
the initial audience constant to reach a desired answer would not be evidence.

Current primary prior art reinforces this decision:
[LearnLib's reuse oracle](https://learnlib.de/learnlib/maven-site/latest/apidocs/de.learnlib.filter.reuse/de/learnlib/filter/reuse/ReuseOracle.html)
already caches queries and reuses system states;
[its ADT implementation](https://learnlib.de/learnlib/maven-site/latest/apidocs/)
and [learning library](https://learnlib.de/) cover reset-aware learning and
alphabet refinement. [Eclipse Thingweb](https://github.com/eclipse-thingweb/node-wot)
already provides multiple standard protocol bindings and data mapping. Adding
these existing mechanisms is useful reuse, not evidence of a newly possible
industry. Prior lab negative/tied results remain unchanged.
