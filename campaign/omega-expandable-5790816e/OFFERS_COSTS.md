## Buyer compute and participation

The implemented finite-machine learner runs locally with Python's standard
library. It requires no model, provider account or network call. The buyer
supplies query permission, a non-destructive reset/query function, alphabet,
state bound and a resource budget. This is a narrow useful workflow, not general
autonomous invention. A buyer cannot safely infer the prerequisites merely from
a passing finite sample.

For every run report learning queries, independent checking queries and
qualification. A query-count tie implies no algorithmic savings. At9920 total
queries,1ms,100ms and1second per query imply respectively9.92seconds,
16.53minutes and2.76hours of oracle time before other overhead. These are latency
sensitivities, not measured device or human times. Electricity, hardware ownership
and buyer attention remain separate. Reset/query side effects or unavailable
hardware can make the workflow unsuitable.

Buyer-funded external model routing remains a broader product requirement, not
implemented provider support in this edition or permission to transmit data.
No external provider is called. Independent adoption/setup effort and compute
costs reduce modeled buyer net benefit. Unknown real buyer effort is not zero.
