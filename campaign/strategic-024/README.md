# Strategic 024: public native commercial experiment

This development experiment connects method selection, price selection and finite
investment allocation to the existing native simulated enterprise. It starts
fresh accounts on the released `main` financial path, preserving its original
protection terms. It does not import PR #35 migration/CAS code or recover an old
private account.

## Fixed experiment

The public workflow first executes both arms for 14 planning days with central
conditions and seed `2610311624`. Once those executions and their independent
operating/financial checks finish, it executes every combination of:

- 28 planning days followed by settlement drain;
- seeds `2610311601` and `2610311602`;
- central, rival-price-parity and adverse collection/delay conditions;
- incumbent `competitive_growth` and the explicitly enabled joint policy.

Each pair receives the same synthetic service inventory, market configuration,
seed, initial capital and native obligation rules. Additional candidate planning,
method and development costs are charged under disclosed model envelopes. The
runner freezes the protocol and configurations in each public receipt; the Git
commit and runtime source inventory identify the implementation. Unfavorable
cases are retained. A negative profit or losing policy is a completed experiment,
not an engineering execution failure. A failed audit or incomplete horizon is not
accepted as a completed result.

The candidate can choose only among its enumerated feasible actions using stated
public beliefs. An optimum inside that finite model is not a globally optimal
enterprise or proof that its demand assumptions match the actual environment.
Rivals, buyers, no-purchase, cash availability and obligations remain explicit.

## Run and inspect

Run the **Strategic 024 public commercial experiment** GitHub Actions workflow,
or invoke `scripts/run_strategic024.py` with the exact stage, case, seed and arm
listed in its fixed protocol. Each invocation needs a new output directory.

Only `public/SUMMARY.json` is uploaded. It includes compact financial, delivery,
source, configuration and audit information. Raw native account authority and
working state remain private to the runner. The Actions job summary displays the
outcome in a browser. The source and compact receipts are the reproducibility
record; bulky historical logs and archives are not required for this experiment.

## Claim limits

All buyers, payments and revenue are simulated. The experiment does not establish
actual commerce, measured frontier-model billing, after-tax complete-campaign
profit, annual scale, capability-invention superiority or the $3 billion
trailing-year profit target. Actual host/model/integration billing remains
unmeasured and must not be silently counted as zero. Native profitable operations,
comparative policy benefit, retained capability benefit and conditional aggregate
scaling are separate findings.

An earlier two-order local development probe on a different integration base
found underpricing and a worse candidate result: modeled enterprise profit
`-$59.445538` versus incumbent `-$36.499777`, including setup. This diagnostic
motivated correcting the public-belief/market interface; it is not confirmation
for this main-based candidate. No successful public outcome is claimed before the
exact public workflow completes.
