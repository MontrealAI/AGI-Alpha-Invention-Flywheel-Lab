# Executed technical services for the portfolio successor

The successor can begin with four source-bound technical qualifications: the existing reconciliation cohort, a real supervisor-driver repair, a small operator guide with a checked example, and a twelve-question technical evidence response. Customer decisions, future order volume, repeated scaled production and money remain simulation assumptions. These artifacts do not establish observed customer acceptance or revenue.

`EXECUTED_SERVICES.json` is the current qualification interface. `executed-002` contains the independently checked packet and the producer/checker source snapshots. `executed-001` preserves the earlier producer-only packet check. Both attempts and their resource receipts remain visible.

| --- | --- | --- |

The repaired expression identifies the existing receipt file. This is a one-line reporting repair, not a full nine-hour software project. |

The guide's embedded capability statements are source-checked. It is not comprehensive migration documentation. |

This is a small public evidence response, not a complete enterprise RFP. |

The market agent authored the driver repair; this portfolio task extracted its exact patch and independently exercised the native supervisor contract. This division is provenance for ordinary engineering, not a claim of autonomous scientific invention.

The RFP checker imports no producer logic. It recomputes source counts, input identities, acceptance and scope flags. Complete rendered-body equality prevents appended unsupported Markdown from escaping checking. Builder and verifier use the same host and model family; no external certification is claimed.

## Reproduce the actual work

```sh
python -m commercial.portfolio_services --output campaign/commercial-011/services/NEW_EXECUTION
python -m unittest discover -s tests -p 'test_portfolio_services*011.py' -v
```

Use a fresh output path. Inputs are public repository evidence and authored synthetic records. There are no provider API calls, customer contacts, private account connections, credential changes or financial transactions. Native supervisor test commands execute locally and preserve success/failure receipts.

`COST_SCOPE.json` makes the narrow human-time and machine-resource assumptions explicit. It uses source-bound PR17 wage proxies, with assumed task hours for these small deliverables. The full-project portfolio prices and 33-hour RFP statistic are not copied into their economics. Human onboarding and all comparable human stages remain human work; one-time context setup is included once. Exact host model routing and bills remain unknown.

Operating envelopes cover preparation, production, checks, corrections, delivery and support. The growth model separately charges acquisition, shared setup/maintenance, one-time onboarding, payment obligations and reserves; none of those may silently disappear. A technically accepted prototype is an input to conditional market simulation, not proof of unlimited delivery capacity or that customers will buy it.
