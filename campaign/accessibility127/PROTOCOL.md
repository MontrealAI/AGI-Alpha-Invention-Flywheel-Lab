## Four routes: hold cash is a first-class competitor

- **A. One-off remediation:** qualified specialists/known vendors remediate actual PDFs, independently check semantic structure and end-user screen-reader tasks; support/correction and disclosure costs count. Existing providers likely cover this; do not claim novelty.
- **B. Source-first born-accessible publication:** maintain structured, approved source facts and render a semantic HTML public counterpart *before* output is locked into an opaque PDF; retain source provenance, exact claim-to-origin mapping and independent replay. Could prevent some future retrofits but cannot repair all existing PDFs without qualified extraction/review.
- **C. Recurring release-integrated accessibility assurance:** track changes, run WCAG tool and manual assistive-technology checks, own correction/maintenance SLA and preserve version audit; competitor is existing managed accessibility platform plus competent human reviewers.
- **D. NO-BID / NO-DEPLOY:** hold funds, avoid ineligible promises, preserve existing capital/liabilities. This wins until eligibility, qualified accepted outcomes, complete costs, reachable demand and competitive value are evidenced.

No win probability, fee, contract, buyer acceptance, capacity, full human/inference labor cost or accessible inventory count is assumed.

## Predeclared finite technical test

Build only a **Python-stdlib source-bound structured-publication renderer** and a **separate offline verifier**. Test a *tiny publicly documented fact set* paraphrasing the above notices, clearly labeled with issuer-versus-secondary evidence grades. The output is a locally produced HTML research fact sheet, NOT a remediation of the original tender PDFs, a bid response, a WCAG 2.1 AA certificate, or accessibility user acceptance.

Immutable acceptance tests before code:
- T0: valid source facts → one deterministic HTML file plus a manifest that binds SHA-256 of exact input bytes and exact HTML bytes.
- T1: independent verifier checks from raw input and manifest; full deterministic reproduction, exact record count, ids and sources. Any output tamper rejects.
- T2: one missing source or a bad URL (including javascript: / http:) rejects before publication.
- T3: duplicate record identifiers or unsupported evidence grades rejects.
- T4: HTML-reserved markup in a title must be escaped; no script injection is permitted.
- T5: one changed fact with old manifest rejects.
- T6: missing required essential fact, invented dollar bid ceiling or invalid temporal structure rejects rather than being silently filled.
- T7: displayed tender budget must be **null / undisclosed**; the Toronto third-party estimate and Vaughan document fee must not become offer revenue, budget or contract award.
- T8: valid generated HTML has one main landmark, hierarchy, table caption, table scopes, language tag, relevant source links, visible evidence-grade warnings and explicit NO-BID verdict.
- T9: independent verifier must fail on tampered HTML even if its original deterministic-looking content remains syntactically valid.

A single fixed input is development, not a held-out cohort. T0–T9 are reproducible **technical** checks; preregistered commercial acceptance remains **FAIL/HOLD** absent actual source-access rights, supplier eligibility, qualified original-document remediation, independent WCAG/user testing, costed strong ordinary comparisons and real voluntary buyer selection. Stop after these cases; retain all failures without cherry-picking.
