# Generated discovery-policy selector

The released construction search policy was developer-written. `mechanisms/policy006.py` adds executable generated **priority programs for choosing investigative actions**, rather than a fixed list of complete workflows. This is a small optional substrate, not the scientific result or a claim that the system learned to invent generally.

`generate(seed, count, parents, omega_source_path)` constructs distinct arithmetic trees by subtree mutation/crossover. `interpret(payload)` ranks the currently available measurement, representation, construction or repair actions and returns an inert action identity or STOP. A fixed trusted domain broker recomputes observations between actions. Thus a generated priority composition can induce a different, observation-dependent experimental sequence. It cannot change the useful objective, authorize an effect, write code or set the acceptance judge.

The finite supplied grammar has six normalized dimensionless features (`gain`, `cost`, `rarity`, `redundancy`, `breadth`, `remaining`), six arithmetic operators, depth6 and47nodes. All features, primitives, action definitions, normalization, provenance labels, broker and generator/adaptor are developer-authored. A predicted gain is explicitly a development-model prediction, never protected confirmation truth. Provenance declarations and hashes are identity evidence; the external domain experiment must establish their actual semantic provenance and uncertainty. No new primitive or scientific novelty follows from generating an arithmetic composition.

`run(policy, broker, budget, source_path, expected_source_sha256)` sends each selection to the existing source-pinned seccomp sandbox. The source initialization and JSON selection run after filesystem, network, process and ambient environment access are denied. The interpreter has no top-level imports or I/O. Only fixed trusted `broker.observe()` and `broker.execute(action_id)` perform domain work outside this selector; the enclosing experiment must qualify and bound that broker. Candidate ASTs cannot execute arbitrary Python. The broker owns actual effects and unchanged acceptance, and must return a strictly bound action/kind/cost/artifact/observation receipt. Failed actions remain charged. Per-kind, step and declared cost limits are external to the candidate. Declared cost units are an authorization proxy, not complete monetary cost; domain CPU, storage, inference and observation costs belong in the enclosing measured run.
