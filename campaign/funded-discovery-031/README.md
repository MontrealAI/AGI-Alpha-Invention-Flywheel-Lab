**Result:** existing discovery/criticism/retention code now executes behind the canonical `JournalAccount` prepayment boundary. This is a proposal-only research API, not default-controller adoption or commercial success.

- Acquisition calls the unchanged `mechanisms.pipeline.develop`: unique structural mapping, bounded construction, real local-file interruption counterexamples, adjudicated criticism, derived repair, fixed verification, inert retention.
- Both reuse arms receive the same retained JSON, donor context, task and search limits. `ordinary_bundle` and `generate_bundle` produce identical candidates and costs. Every candidate is revalidated by the existing fixed verifier; an old capsule is not acceptance or spending authority.
- No-memory uses the strong existing conventional constructor, not an artificially weak baseline. All arms pay the same retrieval/construction envelope; verification is charged for each candidate actually checked. Acquisition is charged once to this study and attributed in full to each reuse counterfactual, with no assumed future amortization.
- Ordinary enterprise behavior is unchanged. `run_research(..., enabled=False)` is the free default. Enabling requires an existing canonical account and explicit seed funding: no unsupported expected-profit claim enables earned-funds spending.

The script creates only a disposable synthetic research account, checks native cost reconciliation/audit, and emits compact inert JSON. No signing key or raw private state is published. No purchase, external API, outreach or business launch occurs. Existing interpreter confinement/hang guards remain; there is no new cumulative CPU approval gate. `RESULTS.json` is local executed engineering evidence, pending composed-source public qualification.
