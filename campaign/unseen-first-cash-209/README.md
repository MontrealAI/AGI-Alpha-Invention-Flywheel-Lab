# FRONTIER Ω FIRSTCASH209 — repeatable, public-data decision kit

**Engineering experiment; not an autonomous invention system or a purchased personalized dossier.** This is the safe next production dependency after the static FIRSTCASH206 sales page and FIRSTCASH207 ten-page example. The central unsolved commercial problem is still independently collected outside-buyer payment, accepted delivery and complete-cost profit.

## What actually runs

No tokens, API keys, merchant login, internet request, native enterprise account or private buyer data are used.

```sh
python3 -B -m unittest -v tests.test_firstcash209_decision_kit
python3 -B tools/firstcash209_decision_kit.py build \
  --case campaign/unseen-first-cash-209/PUBLIC_SELF_CASE.json \
  --output /absolute/NEW/public-self-case
python3 -B tools/firstcash209_decision_kit.py verify \
  --output /absolute/NEW/public-self-case
```

The program creates a canonical CASE.json, decision receipt, ten-page A4-printable EN/FR HTML, and SHA256 manifest. Its `verify` runs offline on these files against the current generator byte identity and rejects tampering/source drift, missing sources, false paid/deployed status and incomplete costs. The source references are **author-submitted** and *not automatically independently fetched*; a declared source digest is not a substituted independent verification. The fixed MONTREAL.AI case has three materially different choices, including no-deploy. Any customer use requires separate permissions, actual inputs and human acceptance. It intentionally cannot render arbitrary imported code, make real financial entries or declare a profit.

The GitHub workflow renders and independently counts real A4 PDF pages from its own checkout head and uploads an ephemeral public self-case bundle. A PDF print is a print-layout verification, not a client deliverable or financial event. Actual source-matched workflow outcome must be inspected; a committed workflow is not evidence of success.

## Strict limitations and next discriminating test

- **Proven if checks pass:** deterministic bilingual source-labelled packaging/replay on a public self-case, with negative and missing-evidence refusal.
- **Not proven:** independent truth of linked publications, frontier discovery, relative effectiveness versus competent analysts/AI software, useful completed buyer work, signed commercial acceptance, reproducible advantage between fresh beneficiaries, paid use, margins or autonomous compounding.
- **Strong alternatives:** a conventional competent human/hybrid assessment, lower-priced published opportunity audits, reusable generic document tools and *no deploy*. Our assembler needs actual cost and outcome parity evidence against them before any value superiority claim.
- **Next real proof:** two distinct genuinely consented and paid customers receiving agreed specialized reports within delivery terms, measured end-to-end production/verification/correction and attributable costs, plus source-verified accepted decisions. In the present no-outreach/no-transaction mandate that proof is a held boundary, not invented.
- **Safety:** the source/report/manifest are non-financial. Existing JournalAccount, key custody, liabilities, PR #40 and protected main/release remain the authority; no alternative money ledger is created.
