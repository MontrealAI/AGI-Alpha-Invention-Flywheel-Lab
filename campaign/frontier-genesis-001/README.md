**See the frontier. Construct the consequence. Test whether the method of seeing has improved.**

This is a **small, executable supporting instrument for the active Blue Sky 064 mission**, not a new autonomous enterprise platform, proof of general AGI, a functioning live science foundry, or the flagship itself. It adds a source-bound frontier observer and an auditable finite opportunity-construction comparison without changing commercial operations or their authoritative ledgers.

## Three orders of intelligence — explicit evidence boundaries

1. **See the frontier:** `watch.py` requests bounded *public GitHub release metadata* from named repositories on demand; it saves sources and dates but marks access and practical ability **UNVERIFIED**. The study's manually inspected primary-source examples distinguish public tools from restricted and internal demonstrations. This observer does **not** monitor the full AI frontier or run automatically.
2. **See the consequences:** `genesis.py` solves for the least-complete-cost sequence of **declared executable operations** leading from installed capabilities to three buyer-outcome hypotheses. Multi-step combinations are discovered rather than supplied as complete paths. Remove one frontier event to estimate its **conditional contribution in the finite game**. Publicly described restricted advances do not enter the usable capability set.
3. **Improve how possibilities are seen:** each accepted candidate for a better proposer, router or planner must compete on independent fresh campaigns against a strong unrestricted frontier agent and ordinary methods, with complete costs. **This release does not yet learn a better discovery policy**; it makes that limit explicit. The exact finite planner is a correct baseline, not a MuZero implementation or a novel algorithm.

## What is optimized, and what is not

- **Exact within stated finite model:** minimum positive-integer-cent construction cost by Dijkstra over a monotone capability set; finite deterministic posted prices with buyers allowed to decline; choose no entry when there is no buyer participation or positive complete margin. The lower-bound price feasibility uses a specified quasilinear outside-option assumption. An independent exhaustive reference checks small graphs.
- **Not established:** optimality over unknown opportunities, unknown tool operations, real buyer demand, stochastic rival response, portfolio coupling, financing, physical qualification, trained world models, model learning or causal improvement of an inventor. A scenario with flawed cost or access inputs can have a mathematically exact but economically wrong answer.
- **Strict gate:** none of this qualifies a real commercial service. An observed customer decision, independent accepted delivery and actual complete-cost collections are separate requirements. Real funding, customer data, outreach or model API access are not created or used.
