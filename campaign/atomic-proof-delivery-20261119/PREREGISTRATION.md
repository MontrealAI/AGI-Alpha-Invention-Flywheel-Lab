## Productive question, not a declared breakthrough

For an **exactly and cheaply checkable digital computational deliverable**, can a seller publish a correct witness, expose it to the buyer, and receive an atomic fee *without requiring the buyer to attest honestly after learning the answer*? Use a bounded **three-coloring witness of a buyer-committed graph** as a concrete NP-certificate example. This is a conventional known mechanism, not proof of market demand, difficulty, unprecedented novelty, frontier AI advantage or commercial value. Research purpose: remove an identified incomplete-acceptance obstacle for machine-to-machine verifiable work, while retaining the strong outside options.

## Fixed test protocol

1. Solidity ^0.8.24 local EVM reference contract accepts a buyer-funded local test ETH escrow with immutable job specification commitment, seller, expiry and stated protocol fee <=250bps. Seller supplies `uint32[]` adjacency rows and `uint8[]` colors; the contract verifies the original committed graph, undirected symmetry, absence of loops, no out-of-range vertices, and every edge's endpoints colored differently with values 0..2. It marks terminal accepted and pays seller/treasury only after successful verification. Buyer may reclaim after expiry only if unaccepted. No counterparties are contacted.
2. Acceptance worlds fixed *before construction*: triangle K3 (three colors necessary, valid seller claim), four-cycle C4 (valid two-color certificate), unsatisfiable K4, malformed asymmetric graph, self-loop, missing edge, wrong graph commitment, too-short and out-of-range colors, unauthorized seller, duplicate identifier, pre-expiry refund, post-expiry refund, acceptance/refund race, reverted seller payout, treasury fee and zero-fee smallest-unit rounding. Preserve source identity and every failed test.
3. A competent conventional software comparator enumerates exactly the same three-coloring specification for fixed small graphs and verifies the same certificate off-chain; any tie remains a tie. Evaluate buyer-controlled verifier escrow, independent-verifier fee escrow, direct conventional solver/self-service and **no deployment** as credible alternative arrangements, without assuming a unique blockchain advantage.
4. Test on a standard public GitHub-hosted runner using the repository's **360-minute** platform window, print `AGI_JOB_START_EPOCH` in the first job step, use `foundry-rs/foundry-toolchain@v1` and `forge test -vv`. Python comparator requires only standard library. Record gas and run resource scope if available; never translate gas to dollars without measured fee conditions.
5. **Precommitted decision:** technical gate passes only if EVM simulated accepted proof results in correct atomic balances, invalid output never settles, expired refund preserves principal, duplicate/replay/unauthorized actions fail, and competent direct software result is not misrepresented as inferior. If a case fails, record it and repair prospectively; do not replace or drop it. No commerce/market or $3B claim is admitted without observed buyer permission, consent, acceptance, rights, complete measured costs and independently verified collections. Never run on mainnet.

## Limits and cost/participation accounting

Seller must fund computation and transaction/gas, buyer must voluntarily fund the task, chain has disclosure/front-running, transaction-ordering, block timestamp, verification gas, reversion and crypto-asset risks. A correct 3-coloring certificate is a narrow syntactic outcome, not economically valuable guaranteed optimization or physical truth. This work does **not** finance any enterprise action with imaginary fees or create a second operating ledger. EVM balances are entirely ephemeral test state. No new paid APIs, spending, real transactions, credentials, publishing to live chain, outreach or production deployment.
