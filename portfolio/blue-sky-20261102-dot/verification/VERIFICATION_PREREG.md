# Independent portfolio verification contract v1

Frozen scope: `portfolio/blue-sky-20261102-dot`; verifier owns this file, not constructor models. Date: 2026-11-02 UTC. This contract precedes receipt of route results. Route-specific numeric tolerances and cases will be frozen after reading interfaces but before their confirmatory evaluation. This is not approval of any physical deployment or business.

## Claims and gates
1. **Runnable construction:** source identities, dependency versions, command, input and output digests; reproducible execution. Reject missing required outputs or silently repaired inputs.
2. **Engineering verification:** dimensions, conservation and analytic/cross-solver agreement on the stated model. Solver success alone is insufficient; independently reconstruct every constraint residual and objective from returned decisions.
3. **Physical validation:** name independent measurements, calibration uncertainty and operating envelope. If unavailable, mark unresolved, even if gate 2 passes. Agreement of solvers sharing equations is not independent physical truth.
4. **Enabling frontier:** compare same required outcome against strongest complete conventional substitute with all permitted transformations, normal automation, build-or-buy and complete costs. A tie is retained and does not reject useful construction; it prevents claiming a unique capability or algorithmic advantage. No invented human time or zero unknown costs.
5. **Different successor:** freeze K1 bytes/state before K2; identify different function and independent reason for greater consequence. Compare retained K1, fresh build, equal-content ordinary reuse, and no claimed mechanism. Improved inference on another draw of the same task is not different K2.
6. **Commercial claims:** none are authorized by these scientific gates. Native account owner/economic adversary must independently qualify acceptance-to-cash linkage, full costs, funding and completed rolling365-day profit.

## Prespecified challenges (route-independent)
- U0: zero useful resources plus positive demanded output must be infeasible/HOLD, never create free production.
- U1: exactly sufficient resources must pass with explicit numerical tolerance; nearby insufficient case must fail or report quantified unmet obligations, not quietly relax them.
- U2: scaling physical units consistently must leave dimensionless decisions and feasibility invariant; scale costs separately to check no unit-conversion windfall.
- U3: resource consumption and useful output must reconcile with stocks, wastes, losses and boundaries. Include terminal inventory, replenishment, startup and future service obligations where relevant.
- U4: enlarging a feasible action set cannot worsen its exact attainable optimum; narrowing cannot improve it except reported solver error. Do not infer pointwise monotonicity where economics/physical law does not imply it.
- U5: add a genuinely binding obligation; candidate cannot win by discarding it. Compare both arms with that obligation.
- U6: remove claimed mechanism while retaining other information/resources; no artificial tool privilege for candidate.
- U7: disturbances within the declared envelope and beyond it, drift, missing/invalid observation, and a coupled nuisance forbidden by the proposed simplification. Report graceful rejection separately from successful productive coverage.
- U8: restart/replay/order changes cannot duplicate capacity, accepted outputs, or resources. K1 inherited state must retain its qualification domain; a changed K2 boundary must trigger revalidation.
- U9: an optimal ordinary method gets the same constructed interface and content. If it ties, attribute to the interface/content, not superior discovery.

## Independence and correction
Shared paths and hashes establish byte identity, NOT secrecy or physical truth. No adversarial fixture in this directory is a protected holdout. Access separation is procedural only; report what constructors saw before freezing. No unseen-world probability claims from adversarial finite cases. For deterministic exhaustive finite cases report counts and worst cases; do not add meaningless confidence intervals. For stochastic samples preregister sampling unit, dependence, seeds, sample size and multiplicity before outcomes; calibration error remains separate.

Verifier will not tune constructor parameters or replace outcome requirements after results. Preserve first failure and source identity. Recoverable implementation repairs get a new version and explicit re-execution; a changed scientific acceptance contract is a new registered comparison. All-reject/HOLD may be safe but is not productive capability. A passing subset cannot conceal the denominator.
