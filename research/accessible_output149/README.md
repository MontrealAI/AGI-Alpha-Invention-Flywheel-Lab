# Accessibility149: real isolated source operation and conservative content continuity

**Status: additive offline research only — NO BID / NO DEPLOY.** This is a
supporting instrument for the Blue Sky ability to deliver an independently

The original Accessibility148 six-file research merged into main but its five

without changing Connected014's source-selection or archive guards.

## What is constructed

An explicit, deterministic, version-bound authored-content continuity veto on
top of the already-audited Accessibility148 structural compiler. A model upgrade
can preserve the numbers of headings, images and tables yet silently change a
link destination, an image description, a table value or advice text.
Accessibility148 intentionally labels such a result PASS_STRUCTURAL_ONLY,
not semantic approval. The new independent reviewer accepts **exact authored
content equality except for an unverified model label** as a narrower
continuity fact. Every authored-content change is held for competent semantic
and assistive-technology checking. Neither branch authorizes deployment, WCAG
conformance or automated assertion that the content is true.

The separate, manifest-bound ZIP contains executable Gate148, Review149,
frozen synthetic inputs, tests, research protocol and this operator guide. It
never includes the native account, simulated account keys, recovery or private
user data. Build, verify and independently run it entirely from an extracted
ZIP with no .git, model API, dependency purchase, customer or real payment.

## Operator (Python 3.12+, standard library)

From the repo root, create the standalone ZIP on a *new path*:

    python3 -B -m research.accessible_output149.standalone build --archive /tmp/accessibility149-new.zip
    python3 -B -m research.accessible_output149.standalone verify --archive /tmp/accessibility149-new.zip
    python3 -B -m research.accessible_output149.standalone smoke --archive /tmp/accessibility149-new.zip

The smoke command verifies every source member, extracts into a new temporary
directory, executes both test suites against only extracted code, compiles two
fixed synthetic records, audits both and runs Review149 in the clean extracted
source. The frozen candidate changes authored text and therefore **must** return
HOLD_AUTHORED_CONTENT_CHANGED_REVIEW_REQUIRED. All test outputs are research
receipts, not customer acceptance. SOURCE_MANIFEST.json records the exact
SHA-256 of every member and a canonical source-root digest; the outer archive
SHA-256 is returned by the command.

For manual inspection of an independently extracted clean source:

    python3 -B -m research.accessible_output148.gate compile --record research/accessible_output148/fixtures/baseline.json --output /absolute/new/base
    python3 -B -m research.accessible_output148.gate compile --record research/accessible_output148/fixtures/candidate.json --output /absolute/new/candidate
    python3 -B -m research.accessible_output149.review --baseline /absolute/new/base --candidate /absolute/new/candidate

**Authorization boundary:** A synthetic or reviewer-written record is not
independent customer acceptance, signed content authorization or observed model
provenance. The reviewer cannot infer semantic equivalence from a hash. Exact
record equality does not prove meaning is correct, WCAG, usability, or
accessibility for people using assistive technologies. Missing content-review
evidence is not silently filled with a favorable assumption.

## Complete alternatives and no deployment

- **Strong specialist provider:** designs, remediates and tests all required
  modalities, including accessible PDFs/forms/video, assistive-technology and
  semantic checks. This research has not beaten or fully costed that route.
- **Conventional post-hoc remediation and independent QA:** can deliver the
  same complete result with human/software review. Measured comparative
  acceptance, time, wages and support remain unavailable.
- **Source-first structured output plus hold gate:** potential reduction in
  avoidable version drift and reproducible delivery, but only HTML structure
  and authored-content identity are locally demonstrated.
- **NO BID / NO DEPLOY:** remains the only supported commercial choice without
  an actual complete-offer acceptance and attainable buyer, cost and funding
  evidence.
