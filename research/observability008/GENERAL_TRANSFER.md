# Real-model construction and fresh development transfer

`compile_petab.py` is a new generalized constructor that reuses the exact arithmetic and fixed MathML evaluator in `gauge_probe.py`. The source and dependency hashes are frozen in `GENERAL_COMPILER_FREEZE.json` before the next selected ratio-observable development test. Elowitz and Crauste are already exposed development models; none of these cases is protected confirmation.

The new compiler constructs ambiguity constraints from actual SBML plus PEtab observation and noise formulas, rather than assuming a GFP observable. It resolves measurement-specific observable/noise parameter aliases, accounts for fixed parameters and unit compartments, and respects literal zero initial conditions. A known nonzero initial concentration constrains a state scaling; a known zero does not. The emitted program is an inert exact-rational `linear-ambiguity-plan/v1` record with explicit conditional calibration requirements and source hashes. Each synthesized observable is an instrument specification, not a newly acquired physical measurement. Unit costs count measurements; they are not money.

Run against a new source directory and a nonexistent output directory:

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 timeout 180 python3 compile_petab.py --source crauste_source --output /tmp/crauste-transfer-NEW
```

`runs/elowitz-general-r1/` reproduces the original Elowitz ambiguity subspace. The old 118 constraints and generalized 31 constraints have exactly the same row space/rank26 in dimension29; `GENERAL_ROWSPACE_EQUIVALENCE.json` records the calculation. Thus the new observation compiler preserves the three known directions while removing the hardcoded observation contract.

`runs/crauste-transfer-r1/` executes the distinct public five-state T-cell differentiation model, twelve estimated parameters and twenty-one measurements. Three states begin at zero and are correctly not falsely fixed by the scaling compiler. The actual measured-state contract plus known positive initial conditions removes the known scale directions, so the correct required measurement plan is empty. This is a useful transfer/refusal to invent missing measurements, not an inheritance advantage or a claim of complete identifiability. A conventional exact method receives the same source and returns the same result.

Both source folders pin PEtab revision `c44d5ede9bf979db5aa8ae4e94fc31fba9776675`; each Crauste data/model file matches its exact upstream Git blob identity. The new digital simulator compares its nominal trajectory with the independent published numerical reference. Elowitz discrepancy is about3.85e-6 absolute; Crauste discrepancy using the PEtab table nominal values is3.9323 cells, approximately2.22e-5 of the largest source reference count. Both meet the numerical validation tolerance coded before these transfer runs (`1e-5 + 1e-4 * maximum-reference magnitude`). The model's SBML and PEtab parameter nominals are slightly different; `SOURCE_PARAMETER_SENSITIVITY.json` preserves both parameter sets and the unchanged-threshold numerical comparison. Neither reference establishes physical validity, model adequacy or commercial consequence.

The compiler conservatively rejects model events, assignment/rate rules, function definitions, condition-specific overrides, non-unit compartments, boundary/constant species, nonpositive estimated parameters and unsupported formula operators. It limits XML nodes, formula nodes, exponent variables, matrix dimensions and row counts. It does not import or execute code from the source model. This is not a general SBML simulator or full identifiability toolbox. Parent-level seccomp qualification applies separately to the emitted bounded rational-plan interpreter.

The homogeneity procedure finds sufficient multiplicative constant-exponent invariances of the individually represented kinetic terms. It can miss more general continuous transformations, term cancellations and finite alternative model/parameter solutions. Absence of this class of invariance is never a certificate of structural/practical identifiability. The known scaling caveat and strong existing methods in `SOURCES.json` continue to govern interpretation.

After Crauste returned the correct empty plan, the next prospective development model was selected as `Boehm_JProteomeRes2014` because its ratio observables exercise a different mathematical observation class. This is selection after a development result, not a population/confirmation test or a reset of the campaign's error budget. The frozen compiler is to run once without outcome-dependent tuning. Any unsupported-model failure is retained under that attempt identity before separately labeled development repair.
