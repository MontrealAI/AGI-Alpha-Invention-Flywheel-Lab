## Frozen discriminator

Within one explicit canonical business evidence scope, after entry, run the following fixed order exactly once. Each call uses the same actual historical source, manifest and authorized ticket. A cold arm clears only the existing in-memory historical receipt cache before invoking the original verification function. A warm arm uses that function's existing cache. Instrument direct subprocess count only by a wrapping observer, with no changes to launch or result. Retain complete result equivalence as a boolean, not receipt bodies.

1. Cold baseline: accepted, direct historical subprocess launched.
2. Warm clean: same receipt, no direct historical subprocess.
3. Warm after adding a same-inode pending alias for an actual referenced published evidence blob: observe acceptance, receipt equality, direct launches, whether the alias was removed and whether the published bytes remained unchanged.
4. Cold with the same valid pending alias (remove only the experiment-created alias between arms): same observations.
5. Warm after adding a separate *unreferenced*, deliberately invalid content-addressed blob and its same-inode pending alias to the disposable store after scope entry: observe whether rejected, whether alias remains, direct launches. No actual reference or existing published blob is modified.
6. Cold with the identical invalid alias: same observations; cleanup only the two experiment-created files.
7. Restored cold: accepted exact baseline receipt, direct launch.

After all arms, check exact local STATE, action tape and connected journal bytes unchanged relative to post-authorization, first migration source inventory unchanged, and original fixture signer inode unchanged (stat only).
