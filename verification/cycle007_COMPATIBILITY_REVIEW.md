# Independent scoped compatibility acceptance

The selected conventional coordinated upgrade passes the unchanged pinned upstream documentation tests and a verifier-controlled behavior panel. Baseline and target each pass all nine original tests and all seventeen protected checks. Their canonical observations agree. Headers/authentication precedence, create/read persistence, rejected-write non-mutation, optional description handling, greeting/closing WebSocket behavior and startup data are exercised. Update/delete and unknown production obligations are outside the source and claim.

The verifier did not edit the candidate dependency specification, application source or original tests. Its fixed cases were held outside the repository until the exact candidate, source manifest, final verifier and protocol hashes were frozen. `FREEZE.json` precedes the first protected execution. `EXPOSED_PROTECTED_CASES.py` now publishes the case source; later runs are exposed reproduction, not fresh confirmation. Protocol v1/v2 proposals were superseded before any case execution, with originals preserved. No statistical superiority claim or confirmation alpha is spent.

Both environments were freshly installed using exactly pinned package versions. The verifier reads actual installed metadata instead of trusting package declarations. Package setup initially failed under the inherited trusted-command supervisor because that supervisor intentionally removes most environment variables: first PATH could not locate uv; after using its absolute executable, proxy removal caused DNS failure. Both failures and receipts remain preserved. A measured setup with the normal approved inherited network environment succeeded. These setup failures consumed no protected cases and do not change the candidate.

Acceptance applies to the official complete tested route. The isolated httpx upgrade failure does not establish a missing enabling invention because the coordinated existing upgrade meets the scoped contract. No security advisory, full application migration, production acceptance, price, real demand, technical superiority or commercial profit is qualified.

Case exclusion is procedural, without OS-enforced builder exclusion, and is not independent external certification.
