# Funded bespoke inventory engineering

This example turns the public OR-License inventory request into 54 inventory policies and six CDC service commitments, independently reconciles the source accounting, and passes the actual output through the existing native funded account. It constructs a useful engineering deliverable; it does not establish customers or economic novelty.

The original request's 95% service line remains diagnostic. A separate, unchanged `QUALITY_CONTRACT_V2.json` offer requires at least347/365 historical joint-service successes for each of48 pairs. The retained quality constructor and a competent ordinary empirical method tie. This is not an out-of-sample service guarantee.

Install optional engineering dependencies and run from a clean checkout using a new absolute private state directory:

```sh
python -m pip install --only-binary=:all: -r requirements-engineering061.txt
python -m inventory061.operate run --root "$PWD" --state-dir /absolute/new/inventory061-state
python -m inventory061.operate reopen --root "$PWD" --state-dir /absolute/new/inventory061-state
python -m unittest discover -s tests -p 'test_inventory061*.py' -v
```

The process funds production before invoking the constructor, checks its actual late-bound policy, and releases only independently accepted output. Its fixed $5,000 offer, consent and buyer budget are explicitly conditional simulation inputs. All existing construction, acquisition, integration, maintenance and support allocations remain; an additional $10,400 unknown-AI cost allocation is charged rather than treating unknown billing as free. The first episode loses money. No purchase is a legitimate separate counterfactual, not a reset or pooled balance.

The fresh operation writes a delivery under `inventory061/deliveries/conditional/` and private recovery authority to the state directory. Retain both for audit/reopen; use another clean checkout for a separately registered fresh episode. Never publish account keys or private recovery state. `deliveries/reference/solution.json` is a portable reference policy, not funding authority or a substitute for fresh construction. Previously exported runs bind their original source and do not qualify this integration.

Public inputs are from [NineAbyss/OR-License](https://github.com/NineAbyss/OR-License), pinned commit `2bda4b8d6ddd4bd1cb62b89acee0c7c2f1914d47`, task13_inventory. Original inputs and accounting programs are retained with their Apache2.0 license; their exact hashes are enforced by `independent_acceptance.py`. Names are public task pseudonyms. No private upload is an input.

The potential new service is an affordable bespoke planning request whose value cannot support conventional engineering. That economic crossover is conditional on complete construction, verification, integration, acquisition, support and error costs plus real willing demand. Microsoft OptiMind and current Gurobi Modeler are strong existing alternatives; a solver-speed result does not prove a proprietary advantage. The unchanged objective remains $100,000 simulated capital to $3billion trailing365-day complete-cost profit; this example does not achieve it.
