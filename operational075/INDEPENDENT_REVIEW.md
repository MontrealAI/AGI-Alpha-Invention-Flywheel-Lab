## Consequential findings corrected before outcomes

1. **Worker JSON was unbound.** The initial broker copied every top-level Python/JSON file but checked only Python hashes between rounds. Retained JSON could therefore change without the host recording it, and a later result JSON could inadvertently enter a worker. The corrected broker has an explicit five-file worker allowlist: package initializer, `ordinary.py`, `retained.py`, `wave.py` and `RETAINED.json`. It hashes the actual copied bytes, binds the worker guard and checks this bundle before each period, on resume and during audit. Arbitrary future-result files are excluded.
2. **Resume validation was narrower than audit validation.** The corrected shared receipt check validates exact period identity, day/round, original-byte count/hash, current-window and state hashes, previous receipt, absence of feedback, worker/guard identities and finite nonnegative resource telemetry before any next policy invocation. An incomplete started period still refuses automatic retry. A synthetically forged period is rejected before further policy work.
3. **Integer parsing differed from the original client.** The original broker converted all numeric confirmation fields through float. It now matches the pinned client: exact integers for round, departure, customer identity, demand and service duration; the original client's `int(float(...))` conversion is retained only for window endpoints. A synthetic customer identifier above the exact-float range remains unchanged.
4. **A safe deferred route was forgotten.** A reviewer-authored twelve-order directed nonmetric fixture first produced a valid next-round whole-route witness. At the next departure, one singleton was infeasible while that known full route remained feasible. The original constructor discarded its own witness and refused because its small-cover fallback admitted at most eleven pending orders. The corrected procedure revalidates the prior witness as a current incumbent, then constructs coverage for newly/uncovered orders. The same independent fixture now dispatches all twelve legally, with 629 full-route checks and driving cost 13. No official outcome was used to select this correction.
5. **Annual volume did not establish dated feasibility.** The initial economic gate checked aggregate yearly reach/capacity while its cash model assumed a particular early admission schedule. The corrected model exposes the exact 365-entry admission vector and hash, and requires independently supported dated demand and execution capacity sufficient on every required day. Annual totals are necessary only. Missing dated facts remain UNESTABLISHED; putting all available quantity on day 364 does not satisfy the plan.
